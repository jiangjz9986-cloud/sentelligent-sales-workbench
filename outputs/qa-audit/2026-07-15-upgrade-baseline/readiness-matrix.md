# 森特智行 AI 销售作战台实施就绪矩阵

更新时间：2026-07-15

## 1. 当前判定

- 产品状态：可运行的单用户 MVP，但尚未达到可正式发布的完整产品标准。
- 视觉状态：PC 与手机“风格一”效果图已生成；真实页面对照审查已完成，等待最终视觉确认。
- 代码状态：本地自动化基线通过，但当前 `.git` 为空目录，无法形成可靠版本和回退点。
- 发布状态：`NO-GO`。在建立源码归档、有效 Git 基线、数据库备份和可验证回退方案前，不进入生产更新。

## 2. 模块差距矩阵

| 模块 | 当前可用能力 | 主要缺口 | 目标操作模型 | 关键验收 |
| --- | --- | --- | --- | --- |
| 战情总览 | KPI、动作、客户、记录、商机、节奏和阶段卡片可跳转 | 桌面仍是 Hero + 卡片；手机 KPI 占满首屏；最近记录未精确载入对应记录 | 行动入口，不单独 CRUD | KPI、任务、商机、风险均携带准确对象上下文；手机首屏出现 4 项 KPI 和至少 3 条今日工作 |

| 下一步动作 | 列表、详情、状态、负责人、截止日期、删除 | “写入本周计划”目前仅导航；状态写入缺版本冲突保护 | 列表 -> 只读详情 -> 修改 -> 来源生成 -> 删除确认 | 写入周计划产生真实周报来源；重复点击不重复写入；失败不提前改变 UI |
| 周报与汇报 | 生成、编辑、保存、Word 导出、知识引用 | 未生成时显示假正文；缺历史列表/可靠重开；导出 token 进入 URL；分析版本选择不确定 | 历史列表 -> 只读详情 -> 修改 -> 选周期和来源新增 -> 删除/作废确认 | 每段可回溯来源版本；刷新可重开；导出不在 URL 暴露会话凭据；定稿后版本冻结 |
| 风险识别 | 列表、详情、诊断、状态流转、处理意见、删除 | 负责人/延期/来源证据的审计不完整；并发状态覆盖；空态未区分未诊断与无风险 | 列表 -> 只读详情 -> 修改 -> 来源生成 -> 删除确认 | 状态流转、处理意见和来源均持久化；错误时不乐观更新；刷新后状态一致 |
| 知识库 | 搜索、列表、详情、CRUD、方案/周报引用 | 引用覆盖策略不清晰；缺引用影响检查和版本；附件/全文检索未实现 | 列表 -> 只读详情 -> 修改 -> 空表单新增 -> 删除确认 | 删除前展示引用；引用可选追加/覆盖/新建；草稿刷新后仍保留来源 |

| 语音转写 | Web Speech 实时识别；不支持时可录音留存；录音上传入口 | 没有正式服务端上传、转写任务、历史音频和清理策略 | 快速记录的输入能力 | 权限拒绝、无语音、上传超限、格式错误、转写超时、重试和资源释放全部可验证 |
| DeepSeek 分析 | 快速记录、周报、方案和建议调用；失败可规则降级 | 原始 PII 直传；降级来源不够显式；缺调用观测、成本、不可变分析版本和真实候选匹配 | 后台能力，结果先只读再人工修改/确认 | UI 明确显示模型/规则降级来源；伪造 ID 被拒绝；超时/429/5xx/非法 JSON 可观测且不泄密 |
| 微信机器人 | 二维码绑定、文本/语音文本记录、客户查询、周报命令 | 草稿和绑定部分驻内存；重启恢复、外部消息幂等、发送者白名单不足 | 绑定状态机 + 持久草稿 | 二维码过期不可复用；重启后草稿和绑定状态可恢复；同一消息只处理一次；解绑后凭据失效 |
| 登录与会话 | 单账号登录、七天缓存、接口保护 | 后端配置缺失可能默认放行；Bearer/URL token；缺安全 Cookie、CSRF、限流和会话撤销 | 登录表单 + 账号菜单退出 | 缺配置启动失败；所有业务接口默认 401；安全 Cookie；注销/过期/刷新重放测试通过 |

## 3. P0 工程阻断项

1. 清除空数据库和接口失败时的静态演示数据回填。
2. 鉴权改为默认拒绝；移除 URL token；建立安全 Cookie 会话与撤销机制。
3. 为所有接口增加请求体上限、字段白名单、长度、枚举和外键校验。
4. 建立事务、幂等键和乐观锁；确认、同步、审计必须完整提交或完整回滚。
5. SQLite 开启 WAL、`busy_timeout`、约束和版本化迁移。
6. 修复快速记录人工修改结果未回写问题，并冻结确认时使用的分析版本。
7. 建立有效源码版本、活动数据库备份及可验证回退点。

## 4. 视觉与交互基线

### 桌面端

- 移除营销式 Hero。
- 顶部使用统一 KPI 指标带，内部竖分隔，不再使用四张独立浮动卡。
- 主要内容使用今日工作表、重点商机列表和风险列表。
- 页面内容在主工作区内部滚动，顶部工具栏和侧栏保持稳定。
- 表格行高约 `44px`，详情/编辑使用桌面右侧 Drawer。

### 手机端

- 顶部 App Bar `56px`，品牌 Logo、搜索入口和头像完整显示。
- KPI 使用一个 `2 x 2` 分组面板。
- KPI 后立即展示今日工作，首屏至少露出三行任务。
- 固定底部五项导航：总览、快速记录、客户、商机、更多。
- “更多”使用 Bottom Sheet 承载动作、周报、风险、知识、看板和微信绑定。
- 手机控件最小 `44 x 44px`；复杂表单使用全屏 Sheet 和固定保存/取消栏。
- 只有商机看板内部允许横向滚动，页面和模块导航禁止横向溢出。

## 7. 验收证据模型

每个可见按钮必须至少产生一种可观察结果：

1. 页面路由或选中状态改变。
2. 明确的展开/收起状态和 `aria-expanded`。
3. API 请求及稳定响应。
4. SQLite 或审计日志变化。
5. 下载文件及其内容校验。

写操作还必须验证：

- 请求中禁用重复提交。
- API 失败时保留用户输入并显示可恢复错误。
- 数据库和审计日志一致。
- 刷新后状态不丢失。
- 服务重启后状态可恢复。
- 两个窗口同时编辑时旧版本返回 `409`，不得静默覆盖。

## 8. 浏览器与设备矩阵

- Chrome/Chromium：`360 x 800`、`390 x 844`、`834 x 1194`、`1024 x 768`、`1440 x 900`。
- WebKit/Safari：同样五个尺寸，重点覆盖麦克风、录音上传、安全 Cookie 和下载。
- 真实设备：至少一台 iPhone Safari 和一台 Android Chrome。
- 异常状态：空库、搜索无结果、401、404、413、422、409、500、502、断网、AI 超时、数据库锁定、二维码过期、麦克风拒绝。

## 9. 版本与回退门禁

1. 源码归档排除 `.git`、`.runtime`、`.env`、依赖、构建产物和数据库。
2. 单独备份活动 SQLite，并验证 `quick_check`、`foreign_key_check`、SHA-256 和恢复启动。
3. 移走空 `.git` 后初始化 `main`，敏感信息扫描通过再建立首个基线提交。
4. 每次发布使用 `YYYYMMDD-HHMM-<short-sha>` 版本号和制品哈希。
5. 生产采用 `releases/<version>`、`current`、`previous` 原子切换；数据库和环境文件位于 shared。
6. 发布后执行服务、Caddy、API、登录、只读查询和隔离写入健康检查。
7. 服务器重启后重复健康检查。
8. 至少演练一次应用回退和数据库恢复，并保存证据与耗时。

## 10. 下一门禁

用户确认 PC 和手机“风格一”后：

1. 将本矩阵转换为正式设计规格。
2. 自审规格中的占位、矛盾、歧义和范围。
3. 用户复核正式规格。
4. 编写详细实施计划。
5. 建立版本和数据库回退基线。
6. 启动互不冲突的多 Agent 实施。

在视觉确认、正式规格和回退基线完成前，不修改业务代码或生产环境。
