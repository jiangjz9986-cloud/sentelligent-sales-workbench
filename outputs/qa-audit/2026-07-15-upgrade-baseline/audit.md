# 森特智行 AI 销售作战台升级前基线审查

审查日期：2026-07-15

## 1. 审查范围

- 本地业务地址：`http://127.0.0.1:5184/`
- 桌面端：`1440 x 1024` 视口下的战情总览
- 手机端：`390 x 844` 视口下的战情总览、快速记录、客户列表和客户只读详情
- 对照基线：已选“风格一”桌面端和手机端效果图
- 自动化基线：部署脚本、后端临时数据库测试、前端构建及本地 QA

## 2. 用户目标与可访问性目标

销售人员应在一个固定工作台内快速看清今日任务、重点商机和风险，并能进入快速记录、客户、商机等业务流程。桌面端强调扫描和批量处理，手机端强调单手操作、44px 触控目标、无页面级横向滚动和稳定的底部导航。

## 3. 当前可确认的优点

1. 登录保护、七天登录缓存、DeepSeek 模式和本地 SQLite 服务均处于就绪状态。
2. 客户流程已经实现“列表 -> 只读详情 -> 修改/删除”的基本模型。
3. 快速记录默认进入语音模式，并提供实时转写、上传录音和文本切换入口。
4. 当前页面在 `390px` 下没有文档级横向溢出，业务内容在固定内容区内纵向滚动。
5. 当前审查期间浏览器控制台没有发现错误或警告。

## 4. 主要 UX 风险

### 4.1 战情总览

- 当前桌面端仍以大面积宣传式蓝色模块作为视觉中心，与已选“风格一”的任务表、商机表和风险列表优先结构不一致。
- 当前手机端首屏被四张独立 KPI 卡占满，用户看不到“今日工作”，关键任务需要大幅下滚。
- 手机端仍复用 11 项桌面导航，侧栏实际宽度为 `1282px`、可视宽度为 `380px`，形成页面内部横向滚动。
- 手机端 Logo 容器宽度为 `48px`、内容宽度为 `96px`，导致品牌图像被裁切成“森特”。

### 4.2 快速记录

- 语音模式默认值正确，但顶栏、横向导航、页面标题、步骤条和模式面板层层叠加，核心“开始转写”未处于最强首屏位置。
- 历史记录和新记录在同一长页面中，移动端缺少更明确的“新建/历史”视图切换。
- 页面文字和辅助说明仍偏多，影响现场拜访后的快速录入效率。

### 4.3 客户流程

- 列表、查看详情、修改和删除入口已经存在，但移动端仍使用卡片套卡片的结构，信息密度低。
- 详情页把每个字段做成独立大卡片，长客户档案需要过多滚动；更适合使用 iOS 分组列表和可折叠区段。
- 返回、修改、删除按钮高度均为 `40px`，低于目标触控高度。

## 5. 可访问性风险

- 当前手机端至少发现 20 个可见交互目标低于 `44px` 高度，包括顶栏按钮、横向导航、返回、修改、删除和部分详情行。
- 横向导航依赖滚动发现隐藏模块，没有稳定的“更多”入口，也缺少清晰的当前位置总览。
- 截图只能确认可见布局，不能证明颜色对比度、屏幕阅读器朗读顺序、焦点返回和语音权限错误恢复已经符合要求。

## 6. 对照结论

### 桌面端

已选效果图使用紧凑 KPI 带、今日工作表、重点商机和风险列表；当前实现仍是 Hero 加分散卡片。升级应保留现有模块和数据能力，但重排首页信息结构。

### 手机端

已选效果图将 KPI 合并为 `2 x 2` 分组面板，并在首屏展示三条今日工作，底部固定五项导航。当前实现与该结构差距明显，手机端应作为独立布局处理，而不是桌面侧栏的横向缩小版。

## 7. 自动化基线结果

- `npm run test:deploy`：14/14 通过，敏感信息扫描 112 个文件无发现。
- `npm --prefix backend test`：44/44 通过。
- `npm --prefix outputs/product-design-prototype run qa:local`：构建和全部本地测试通过，前端敏感信息扫描 136 个文件。
- `npm run dev:status`：前端 200、数据库 ready、DeepSeek 模式 ready、登录保护启用。

上述结果证明现有代码具备可运行基础，但不能替代真实视觉、完整按钮矩阵、异常状态、持久化刷新、重启恢复和生产回退验收。

## 8. 审查步骤与健康状态

1. 桌面战情总览：功能可进入，信息结构需重构。
2. 手机战情总览：功能可进入，首屏效率和导航结构不合格。
3. 手机快速记录：语音默认状态正确，首屏层级和长度需优化。
4. 手机客户列表：查询与详情入口可用，卡片密度和导航需优化。
5. 手机客户只读详情：修改/删除模型正确，信息组织和触控尺寸需优化。
