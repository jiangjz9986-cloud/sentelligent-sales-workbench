# 森特智行 AI 销售作战台开发实施方案

## 1. 开发目标

开发目标不是做一个传统 CRM，而是做一个可落地的 **AI 销售作战台**。第一版要让销售团队能够完成以下闭环：

1. 建客户。
2. 建商机。
3. 录入沟通纪要。
4. AI 提炼结构化结果。
5. 自动生成风险和下一步动作。
6. 生成周报草稿。
7. 管理者查看商机盘面和风险。

## 2. 推荐技术架构

### 前端

建议：

- React + Vite 或 Next.js。
- TypeScript。
- Tailwind CSS 或 CSS Modules。
- Zustand / Redux Toolkit 管理页面级状态。
- TanStack Query 管理接口请求与缓存。
- ECharts / Recharts 做图表。

前端核心职责：

- 展示客户、商机、纪要、动作、风险、周报和看板。
- 提供可编辑表单和工作流操作。
- 展示 AI 生成结果、来源引用和人工确认状态。

### 后端

建议：

- Node.js NestJS / Fastify，或 Python FastAPI。
- PostgreSQL 作为主数据库。
- Redis 处理任务队列、缓存和 AI 异步任务状态。
- 对象存储保存附件、会议纪要原文、方案材料。

后端核心职责：

- 业务数据读写。
- 权限控制。
- AI 调用编排。
- 知识库检索。
- 任务队列与日志。
- 生成内容审计与来源追踪。

### AI 层

建议设计成独立 AI Service：

- Prompt 模板管理。
- 模型供应商适配。
- 结构化输出校验。
- 知识库检索增强。
- AI 调用日志。
- 失败重试和降级。

模型密钥必须通过后端环境变量配置，不能进入前端代码、文档或客户端配置。

## 3. 系统模块划分

### 3.1 客户模块

功能：

- 客户基本信息。
- 组织架构。
- 联系人和关系强度。
- 历史项目。
- 基础架构。
- 痛点和预算节奏。
- 决策链。

关键页面：

- 客户列表。
- 客户画像详情。
- 联系人关系图。
- 客户历史记录。

### 3.2 商机模块

功能：

- 商机创建和编辑。
- 阶段管理。
- 金额、赢率、预计回款。
- 需求、方案方向、竞争对手。
- 风险和动作。
- 商机时间线。

关键页面：

- 商机档案。
- 商机看板。
- 商机详情抽屉。

### 3.3 沟通纪要模块

功能：

- 录入拜访、电话、微信、会议纪要。
- 上传附件。
- AI 提炼客户诉求、明确事项、风险点、待办动作。
- 支持人工修订。
- 支持回写商机。

关键页面：

- 沟通纪要录入。
- AI 提炼结果。
- 纪要历史。

### 3.4 动作模块

功能：

- 下一步动作生成。
- 动作分配、截止时间、完成状态。
- 动作来源说明。
- 超期提醒。

动作来源：

- AI 纪要。
- 商机阶段。
- 风险识别。
- 人工创建。

### 3.5 风险模块

功能：

- 风险自动识别。
- 风险等级。
- 风险证据。
- 处理建议。
- 风险状态跟踪。

风险类型：

- 决策链缺失。
- 预算不清。
- 时间节点不明。
- 竞品强势。
- 售前资源不足。
- 方案资料不足。

### 3.6 方案辅助模块

功能：

- 沟通提纲生成。
- 售前问题清单生成。
- 方案框架生成。
- 汇报材料大纲生成。
- 竞品应对话术生成。
- 知识库引用。

### 3.7 周报模块

功能：

- 自动生成销售周报。
- 生成管理摘要。
- 引用来源追踪。
- 人工编辑。
- 导出 Word/PDF。

### 3.8 知识库模块

功能：

- 产品资料管理。
- 厂家方案管理。
- 成功案例管理。
- 投标模板管理。
- FAQ 管理。
- 客户话术管理。
- 向量化检索。

### 3.9 管理汇报模块

功能：

- 总体商机盘面。
- 预计回款。
- 重点商机。
- 卡点风险。
- 资源协调事项。
- 团队动作完成率。

## 6. AI 工作流设计

### 6.1 AI 沟通纪要分析

输入：

- 原始沟通内容。
- 客户画像。
- 商机当前阶段。
- 历史沟通摘要。

输出：

- 客户诉求。
- 明确事项。
- 风险点。
- 待办动作。
- 需要补充的字段。
- 建议写入商机的更新项。

处理方式：

1. 后端接收原文。
2. 写入 Interaction。
3. 创建 AI 分析任务。
4. 调用模型输出 JSON。
5. 校验 JSON 结构。
6. 写入 AiInsight。
7. 用户确认后回写 Opportunity、Risk、ActionItem。

### 6.2 风险识别

输入：

- 商机档案。
- 客户画像。
- 最近沟通纪要。
- 当前阶段。
- 动作完成状态。

输出：

- 风险类型。
- 风险等级。
- 证据。
- 建议动作。

### 6.3 周报生成

输入：

- 本周商机变化。
- 本周沟通纪要。
- 本周完成/未完成动作。
- 本周新增/关闭风险。

输出：

- 管理版周报。
- 销售个人版周报。
- 来源引用。

## 7. 权限设计

建议角色：

- Admin：系统配置、用户管理、所有数据。
- SalesManager：团队商机、汇报、风险、资源协调。
- Sales：自己的客户、商机、动作和周报。
- Presales：被分配的商机、方案辅助、技术资料。
- Viewer：只读管理视图。

权限原则：

- 销售只能编辑自己负责的数据。
- 管理者可查看团队数据。
- AI 生成内容需记录创建人、模型版本和来源。
- 敏感配置只允许管理员管理。

## 8. 安全与合规

必须实现：

- 模型密钥后端环境变量管理。
- 前端不出现任何密钥。
- AI 调用日志脱敏。
- 客户资料访问权限控制。
- 附件上传大小和类型限制。
- 操作日志。
- 生成内容来源追踪。

## 10. 迭代计划

### 第 1 阶段：产品原型与数据底座

周期：1-2 周。

交付：

- 可点击前端原型。
- 客户、商机、动作、风险、纪要基础数据模型。
- Mock 数据流。

### 第 2 阶段：MVP 业务闭环

周期：3-5 周。

交付：

- 客户画像。
- 商机档案。
- AI 沟通纪要。
- 下一步动作。
- 风险识别。
- 周报生成。
- 商机看板。

### 第 3 阶段：知识库与方案辅助

周期：2-4 周。

交付：

- 知识库资料管理。
- 资料检索。
- 方案框架生成。
- 竞品应对话术。

### 第 4 阶段：管理视图与团队协同

周期：2-3 周。

交付：

- 管理汇报视图。
- 团队维度回款预测。
- 资源协调事项。
- 权限和团队管理。

## 11. 验收标准

MVP 验收建议：

- 销售能创建客户和商机。
- 销售能录入一段沟通纪要并得到结构化分析结果。
- 系统能从分析结果生成动作和风险。
- 销售能确认或编辑 AI 结果。
- 周报能引用本周商机、纪要、动作和风险生成草稿。
- 管理者能查看重点商机、预计回款、卡点风险和资源协调事项。

## 12. 风险与建议

主要风险：

- 过早做成传统 CRM，导致复杂但不好用。
- AI 输出不可追溯，用户不敢信。
- 知识库质量不足，方案生成效果不稳定。
- 前端只展示结果，不解释动作来源。

建议：

- 先做销售推进闭环，再扩展资料和管理能力。
- 所有 AI 输出都必须有来源和可编辑机制。
- 风险和动作必须可解释。
- 周报优先做“草稿生成 + 来源引用”，不要直接做不可编辑终稿。
