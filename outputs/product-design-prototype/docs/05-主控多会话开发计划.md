# 主控多会话开发计划

## 1. 主控目标

本项目按“主控窗口 + 专项会话”推进。主控窗口负责规划、调度、代码审查、功能测试、逻辑关联性检查、UI 风格把关、WSL 部署验收和数据库方案收口。

第一阶段目标不是一次性做成复杂 CRM，而是完成一个可运行的轻量版 AI 销售作战台：

- 前端保持已确认的 Apple-style 企业工作台风格。
- 快速记录作为唯一直接 AI 分析入口。
- AI 分析必须手动确认，不自动写入业务数据。
- 客户画像、商机档案、动作、风险、周报形成闭环。
- 后端部署在 WSL Ubuntu-24.04。
- 数据库第一版使用 SQLite，后续需要多人并发或权限复杂化时再迁移 PostgreSQL。

## 3. 主控验收门槛

每个功能进入主控集成前，必须满足：

- `npm run build` 通过。
- 对应功能测试通过。
- 不引入前端明文模型密钥。
- 不恢复全局 AI 抽屉。
- 不恢复 macOS 红黄绿窗口点。
- 100% 缩放下核心桌面和移动视口无页面级横向溢出。
- 新增业务字段必须能在数据层、页面呈现层和交互跳转中闭环。

## 4. 后端与数据库路线

### 4.1 WSL 环境

当前主控已确认：

- WSL 默认发行版：Ubuntu-24.04。
- WSL 版本：WSL2。
- WSL 内 Node：`v24.14.1`。
- WSL 内 Python：`3.12.3`。
- 系统 `sqlite3` 命令暂未安装。
- Node 内置 `node:sqlite` 可用，但有实验性提示。

### 4.2 第一版后端建议

第一版采用 Node 轻量后端：

- `backend/src/server.js`：HTTP API 入口。
- `backend/src/schema.sql`：SQLite 表结构。
- `backend/src/seed.js`：初始化演示数据。
- `backend/src/quickRecordAnalysis.js`：AI mock 分析，占位真实模型调用。
- `backend/.env.example`：只写变量名，不写真实密钥。

第一版数据库实体：

- `customers`
- `contacts`
- `opportunities`
- `interactions`
- `ai_insights`
- `action_items`
- `risks`
- `weekly_reports`
- `sync_events`

关键 API：

- `GET /api/customers`
- `GET /api/opportunities`
- `POST /api/interactions`
- `POST /api/interactions/:id/analyze`
- `POST /api/ai-insights/:id/confirm`
- `GET /api/reports/weekly`
- `POST /api/reports/weekly/generate`

## 5. 集成顺序

1. 底座模块化收尾，冻结文件边界。
2. 快速记录完成 UI 与模型联动。
3. 客户/商机补齐契约字段并通过测试。
4. 后端/数据库建立最小 API 和 SQLite 初始化。
5. 前端接入后端 mock API，替换部分静态数据。
6. QA 会话执行构建、测试、响应式、敏感扫描、WSL 启动检查。
7. 主控做最终代码审查和浏览器验收。

## 6. 当前风险

- 多个 local 会话同时修改同一工作区，存在文件覆盖风险。主控必须及时读取当前状态，而不是只相信单个会话回复。
- 客户/商机专项已经新增失败测试，未完成前不能宣称核心业务闭环完成。
- WSL 数据库第一版不宜过早引入 PostgreSQL/Redis，否则会拖慢原型落地。
- 项目需求书中存在敏感模型配置，后续任何会话都不得把密钥写入前端、文档、截图或日志。
