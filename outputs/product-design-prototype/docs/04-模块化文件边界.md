# 模块化文件边界说明

## 当前目标

本轮只完成低风险模块化整理，保持页面行为、业务文案和已确认的 Apple 风格基本不变。后续专项会话应按文件边界协作，避免把数据、页面、通用组件和样式重新混在 `App.jsx` 中。

## 文件归属

- `src/App.jsx`
  - 只负责应用外壳、顶部栏、侧边导航、全局状态、搜索过滤和当前页面装配。
  - 不新增具体业务页面 JSX，不新增静态业务数据，不新增通用 UI 组件实现。

- `src/data/salesWorkbenchData.js`
  - 存放导航、客户、商机、动作、方案、风险、知识库、周报和看板等静态原型数据。
  - 后续如需接入接口，应先保留字段结构，再在专项会话中单独替换数据来源。

- `src/components/primitives.jsx`
  - 存放跨页面复用的基础展示组件，例如 `Panel`、`MetricCard`、`MetricInline`、`ManualConfirmBox`、`Timeline` 等。
  - 只放通用组件，不放某个业务页面独有的布局。

- `src/features/salesWorkbench/pages.jsx`
  - 存放销售作战台各业务页面和页面内小组件，例如总览、快速记录、客户画像、商机档案、周报、风险、知识库、看板。
  - 页面可以引用 `data/` 和 `components/`，但不要反向让通用组件依赖具体页面。

- `src/styles/global.css`
  - 存放当前原型全局样式和响应式规则。
  - 本轮未拆分 CSS 规则，后续如做视觉专项，再按页面或组件逐步拆分，避免一次性大改影响已确认风格。

- `src/quickRecordModel.js` 与 `src/quickRecordModel.test.js`
  - 保留为快速记录相关逻辑和测试文件。
  - 本轮未调整其业务字段细节。

## 后续协作建议

- 做页面专项时优先改 `src/features/salesWorkbench/pages.jsx`，必要时再补通用组件。
- 做数据或字段专项时优先改 `src/data/salesWorkbenchData.js`，不要在页面里散落新静态数据。
- 做视觉专项时优先改 `src/styles/global.css`，并保持 Apple 风格、低圆角、紧凑工作台密度。
- 涉及模型密钥、生产配置或敏感信息时，只能放后端环境变量，不能写入前端代码、文档或设计稿。
