## 运维注意事项（现行）

- **`.production-cutover.lock` 残留属正常现象**：项目根下该 0 字节文件是 cutover 脚本的 flock 锚点（例如 mtime 08-23 的残留），锁本身随进程释放，文件不自动删除。看到它不代表有未完成的切换；判断切换状态以 `.maintenance-lock` 是否存在与 `ps aux` 中有无 cutover/preflight 进程为准。可在发布窗口顺手 `rm`，也可保留。
- **服务器构建必须 `LC_ALL=C`**：服务器 git 1.8 在中文 locale 下的报错文案会绕过发布脚本的英文正则（v0.7.4 踩坑）。
- **每日备份**：`sentelligent-daily-backup.timer` 每日 02:30（Asia/Shanghai）自动备份数据库与微信会话到 `backups/daily/`，14 天保留；发布制品自动归档到 `backups/releases/<version>/`（root:root 0700）。发布窗口与 02:30 重叠时备份 fail-closed 跳过（cutover 自带备份兜底）。
- **系统 sqlite3 3.7.17 不得触碰 WAL 生产库**：一律用项目 runtime node（≥24）的 `node:sqlite`。
- **受保护边界**：共享 Caddy（如需变更用 restart 显式操作）与轻氧 `qingyang-store` 勿动；CodexAccountVault 家族已于 v0.8.3 窗口退役，部署脚本受保护清单已同步收敛。
