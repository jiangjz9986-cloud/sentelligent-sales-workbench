# v0.4.1 开发与换机交接

## v0.4.1 production hardening

- The preflight and cutover validators now match the live CentOS 7 unit contract: `PrivateTmp=true`, isolated `frontend.env`, and the fixed non-secret WeChat `HOME` assignment.
- Backend credentials remain restricted to the backend/weixin environment file; the frontend cannot consume that file.

更新日期：`2026-08-08`

本文档是可提交到 GitHub 的无密钥交接记录。它记录代码边界、外部联调和新设备恢复方式，不保存任何密钥、Token、密码、Cookie、数据库或业务原件。

## 版本范围

- 目标版本：`v0.4.1`（基于已发布的 `v0.4.0`）
- 开发分支：`codex/v0.4.1-production-cutover-fix`
- 可部署来源：合并后的 `main` 与其注释标签 `v0.4.1`
- 业务边界：单账号个人使用，按自然周管理差旅费用、多笔实付、请款、付款凭证、发票与打印。

## 本版本已实现

- 差旅费用、多笔实付、资金来源、提前请款和多退少补。
- 稳定 `EXP-...` 账单编号，可搜索、复制，并贯通 CSV、A4 付款记录和发票匹配。
- 付款图片/PDF 手工上传、微信待处理、原件预览、人工确认与拒绝。
- 发票仓库、人工复核、精确账单编号匹配、无票确认和周替代候选。
- 付款 PDF Canvas 认证渲染、失败重试门禁与发票 A4 每页四个固定槽位。
- 图片/PDF 原始字节保存，Brotli 仅在严格变小时使用，按 owner + SHA-256 去重，读取时校验长度与摘要；完整 OCR/PDF 文本保留供人工复核，模型请求副本限制为最多 200,000 个字符。
- iCost 只写文本 Webhook，只接受账本“出差报销”，带独立 Token、幂等、限流与审计。
- 统一 iCost 快捷指令的无密钥 unsigned 制品、构建器和验证器。未知账本不请求任一业务系统。

## 明确延后

- 多人、多角色、报销审批流和财务付款。
- 公司餐费、住宿、招待费额度与超标规则；当前没有经用户确认的正式标准，不能硬编码。
- 无人值守的自动发票冒用或自动报销决策；第一版坚持人工确认。
- 通用的付款凭证、微信待处理和发票物理硬删除工具。界面删除为可审计软删除。
- 完整销售决策 Agent V1 运行时拆分、长期录音资产恢复和通用微信消息草稿持久化。

## 新设备恢复

1. 安装 Git、GitHub CLI、Node.js 24 与 Chrome。
2. 从 `https://github.com/jiangjz9986-cloud/sentelligent-sales-workbench.git` 克隆，并检出 `v0.4.1` 或后续开发分支。
3. 在后端和前端目录分别执行 `npm ci`。
4. 从原设备安全转移私密环境文件和 SSH 私钥；核对 SHA-256 与 ACL，不要通过 GitHub、聊天文本或公开网盘传输。
5. 根据 `backend/.env.example` 补齐本机配置，然后运行 `npm run qa:full`。
6. 生产发布前重新采集备份、服务保护快照和预检；不复用旧设备上的时效性证据。

## 仅私下转移的配置

- `backend/.env` 或对应私密环境文件。
- `ssh.pem` 或后续轮换的 SSH 私钥。
- `MODEL_API_KEY`、`AMAP_WEB_SERVICE_KEY`、`AUTH_PASSWORD_HASH`、`AUTH_SESSION_SECRET`、`WEIXIN_AGENT_API_TOKEN`、`ICOST_WEBHOOK_TOKEN`。
- 前端本地所需的 `VITE_AMAP_WEB_JS_KEY` 与 `VITE_AMAP_SECURITY_CODE`。
- 生产数据库、一致性备份、微信会话目录和业务原件不属于代码交接包，需独立受控迁移。
