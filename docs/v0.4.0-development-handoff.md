## v0.4.3 CentOS 7 cutover compatibility

- The cutover validator reads one complete `systemctl show <service>` snapshot and extracts allowlisted properties locally, avoiding unsupported CentOS 7 single-property selectors for newer systemd fields.
- An absent `DynamicUser` field on systemd 219 is treated as an unsupported and therefore disabled feature; `DynamicUser=yes` and unknown values remain rejected.
- The legacy singular `EnvironmentFile=` key remains supported, while missing, duplicate, or additional environment bindings remain fail-closed.
- The preflight and cutover validators now match the live CentOS 7 unit contract: `PrivateTmp=true`, isolated `frontend.env`, and the fixed non-secret WeChat `HOME` assignment.
- Backend credentials remain restricted to the backend/weixin environment file; the frontend cannot consume that file.
- The frontend environment path is pinned to the canonical project `frontend.env`, and suffix-matching path aliases are rejected.
- The schema-2 current-release compatibility path rejects every dependency or other file absent from its hash inventory.
- Legacy and candidate release trees are frozen as `root:root`; cutover rejects any candidate that was not already frozen before complete manifest hash verification.

## 本版本已实现

- 差旅费用、多笔实付、资金来源、提前请款和多退少补。
- 稳定 `EXP-...` 账单编号，可搜索、复制，并贯通 CSV、A4 付款记录和发票匹配。
- 付款图片/PDF 手工上传、微信待处理、原件预览、人工确认与拒绝。
- 发票仓库、人工复核、精确账单编号匹配、无票确认和周替代候选。
- 付款 PDF Canvas 认证渲染、失败重试门禁与发票 A4 每页四个固定槽位。
- 图片/PDF 原始字节保存，Brotli 仅在严格变小时使用，按 owner + SHA-256 去重，读取时校验长度与摘要；完整 OCR/PDF 文本保留供人工复核，模型请求副本限制为最多 200,000 个字符。
- iCost 只写文本 Webhook，只接受账本“出差报销”，带独立 Token、幂等、限流与审计。
- 统一 iCost 快捷指令的无密钥 unsigned 制品、构建器和验证器。未知账本不请求任一业务系统。

## 明确延后

- 多人、多角色、报销审批流和财务付款。
- 公司餐费、住宿、招待费额度与超标规则；当前没有经用户确认的正式标准，不能硬编码。
- 无人值守的自动发票冒用或自动报销决策；第一版坚持人工确认。
- 通用的付款凭证、微信待处理和发票物理硬删除工具。界面删除为可审计软删除。
- 销售决策更多场景 playbook、行业评估集与持续校准，长期录音资产恢复和通用微信消息草稿持久化。

## 新设备恢复

1. 安装 Git、GitHub CLI、Node.js 24 与 Chrome。
2. 从 `https://github.com/jiangjz9986-cloud/sentelligent-sales-workbench.git` 克隆，并检出 `v0.4.4` 或后续开发分支。
3. 在后端和前端目录分别执行 `npm ci`。
4. 从原设备安全转移私密环境文件和 SSH 私钥；核对 SHA-256 与 ACL，不要通过 GitHub、聊天文本或公开网盘传输。
5. 根据 `backend/.env.example` 补齐本机配置，然后运行 `npm run qa:full`。
6. 生产发布前重新采集备份、服务保护快照和预检；不复用旧设备上的时效性证据。
