## 状态定义

- `已开发 / 待合并`：代码和定向验证完成，仍保留在独立分支或本聚合分支。
- `评审中`：已建立 Draft PR，等待逐项确认；不自动合并、不部署。
- `可合并`：用户明确确认范围，且目标分支的合并门禁已满足。
- `已合并`：只能在 GitHub 回读确认合并后登记，不能凭本地状态推断。
- `阻塞`：记录具体证据和阻塞原因，不用“看起来完成”替代。

## 新功能登记规则

1. 每个功能先在自己的工作树和分支完成，保留可回退的提交。
2. 只把明确属于该功能的文件带入聚合分支；不要使用未审查的全量暂存。
3. 登记来源分支、来源提交、目标分支、变更摘要、验证命令和结果。
4. 明确写出“已做什么”和“没有做什么”，尤其是写入、生产、外部服务和财务边界。
5. 更新本 README 的表格，并复制[功能登记模板](./功能登记模板.md)创建一张功能卡。
6. 聚合分支只保持未合并状态；未经用户明确确认，不合并、部署或重启生产。

## 合并前检查

- 确认功能卡与实际提交一致。
- 在正确的包目录执行定向测试和全量测试。
- 检查 `git diff --check`、敏感信息、owner 隔离和副作用边界。
- 回读 Draft PR 的目标分支、文件列表、检查状态和是否仍未合并。
- 只有用户明确批准后，才进入合并或发布流程。
