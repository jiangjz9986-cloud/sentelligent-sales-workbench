# 森特智行 v0.6.17 微信付款图片尾部规范化热修

## 问题

微信 provider 返回的一张付款 JPEG 在解密后包含 24 字节 trailer。JPEG 本体具有正常 SOI/EOI，但现有严格媒体检查会把 EOI 后的附加字节判为无效图片，导致图片在进入记账后端前 fail-closed。

## 修复合同

- 规范化仅发生在 vendored SDK 的 IMAGE 路径中，位于解密或下载之后、临时文件保存和 SHA-256 计算之前。
- 只有以下条件同时满足时剥离最后 24 字节：文件以 `FF D8` 开始；`FF D9` 恰好位于 trailer 之前；trailer `[4:8]` 全零；trailer `[8:24]` 与 JPEG 本体 MD5 固定长度匹配。
- trailer `[0:4]` 不作为固定 magic；实际 provider 值可能变化。摘要通过等长 `timingSafeEqual` 比较。
- 任一条件不匹配时保持原字节，继续由现有 `readWeixinDocument` 严格检查拒绝，不尝试截断、重编码或猜测修复。
- 规范化后的 SHA-256、消息递送身份和付款凭证内容均基于去除 trailer 的 JPEG 本体。

## 回归门禁

- 使用仓库内可通过生产检查的 `VALID_JPEG`，验证已确认 trailer 被精确剥离，保存字节和 SHA-256 均基于 JPEG 本体，并能通过 `readWeixinDocument`。
- 验证 trailer 前四字节变化不会误收窄已确认合同。
- 分别验证 MD5 不匹配、零字段不匹配、SOI 不匹配和 EOI 位置不匹配时不剥离，且由生产文档检查 fail-closed。
- 保留 v0.6.16 的同批回复投递失败隔离、后续消息处理和 cursor commit 回归门禁。

## 边界

- 基线为生产 `v0.6.16` exact commit `19ea795a6f4d6f7c2fc59e27fe5612a2a69523a9`。
- vendored SDK 版本升至 `0.5.0-sentelligent.7`；公共类型不变。
- 无数据库迁移，不删除或重建微信 session、sync cursor、数据库事件、记账草稿、outbox、付款凭证或发票记录。
- 不改变“小小”记账的人工确认、自然周、借款、报销或发票匹配合同；不接入“整理报销”会话开发内容。
- 按项目所有者明确授权使用本地 exact-commit 生产发布路径，不同步 GitHub。
