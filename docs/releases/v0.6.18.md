# 森特智行 v0.6.18 微信远程媒体类型热修

## 问题

`v0.6.17` 已能把微信 provider 的受验证 JPEG trailer 精确剥离，但微信 worker 的远程 Agent 在把该本地文件规范化为 HTTP 事件时遗漏了服务端必需的 `media.type`。图片字节、MIME、SHA-256 和 Base64 都正确，事件仍会在 `/api/integrations/weixin-agent/events` 的严格媒体校验处以 `media` 字段无效拒绝。

## 修复合同

- `normalizeMedia` 在读取本地媒体前直接检查 `request.media.type`，只接受完全匹配的 `image` 或 `file`，不 trim、不推断、不根据扩展名改写类型。
- HTTP 请求体原样携带上述兼容类型，并继续只携带规范化后的文件名、实际媒体类型、无损 Base64、SHA-256 和服务端 source reference；本地 `filePath` 不跨越远程边界。
- 服务端 `validateWeixinAssistantEvent`、格式白名单、文件魔数、声明 MIME、大小上限、路径禁止和 Base64 规范性检查均保持原合同，未放宽任何校验。

## 回归门禁

- 使用真实 JPEG fixture 写入本地文件，走 `filePath -> createRemoteClawbotAgent -> HTTP JSON body -> validateWeixinAssistantEvent` 闭环，验证最终 `mediaType=image/jpeg` 且 `contentBase64` 与原字节完全一致。
- 通过真实本地 HTTP server 的 `/api/integrations/weixin-agent/events` 再走一次远程 Agent 图片请求，验证返回付款凭证响应并形成固定格式待记账草稿。
- 验证远程请求体携带 `type=image` 且不携带 `filePath`。
- 验证 `image` 和 `file` 两个精确值可以转发，而带空格、大小写变体和不支持类型在发起 HTTP 请求前拒绝。

## 边界

- 基线为生产 `v0.6.17` exact commit `ee9ed8d7164cfa7e4d7f0fed0ccef379d9c09b5c`。
- 无数据库迁移，不删除或重建微信 session、sync cursor、数据库事件、记账草稿、outbox、付款凭证或发票记录。
- 不改变“小小”记账的人工确认、自然周、借款、报销或发票匹配合同；不接入“整理报销”会话开发内容。
- 按项目所有者明确授权使用本地 exact-commit 生产发布路径，不同步 GitHub。
