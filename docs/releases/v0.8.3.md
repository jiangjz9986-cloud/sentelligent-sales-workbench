## 关键裁定与设计偏差

- **依赖漂移重核结论（设计第 14 点）**：对 v0.8.2 刚整改过的 `TravelExpensePage.jsx`/`ExpenseEditorDrawer.jsx` 以当前代码重核——`createDraft(expense, weekStart)` 签名、`regionSettingsOpen` 状态、`expense-page-alerts` 容器与 `expense-page-alert is-warning` 样式、`loadWeek`/`selectWeek` 的周失效语义全部在位，接线按语义位点落地；`TravelExpensePage` 此前不接收路由参数，本版新增 `expenseDraft`/`onExpenseDraftConsumed` 两个 prop 而非直接透传 routeFilters。视觉 token 以 v0.8.1 实际落地变量为准（`--radius-card/--radius-control/--radius-chip/--blue #2f6bff` 等），设计文中的 `#2f6fed` 色票不再出现。
- **今日焦点空态**：任务摘要"空段省略"与施工图 §2.1"每分区显示空态短文案"存在措辞差，按施工图定稿执行——四分区常驻、空分区显示"今日无行程"等引导句式（明细行省略），与 audit P1-4 空态规范一致。
- **桌面网格补位**：移除"本日推进节奏"卡后第四行只剩最近记录/重点商机两张 span-4 卡（原三卡填满 12 列），dense flow 无法凭空补 4 列，故两卡升为 span 6；今日焦点/周趋势按设计落第三行 span 6+6。移动端保持既有 KPI→hero 前缀顺序（v0.8.1 已验收现状优先），新卡插在客户温度之后、漏斗之前。
- **`rhythm` 字段去留**：合同 `dashboardSummary.rhythm` 仍为必需键、后端继续输出（微信/历史消费面零涟漪），仅 web 总览不再渲染；`overview-rhythm`/`rhythm-*` 死样式随组件删除（对齐 v0.8.2 删除 weixin-review-* 样式族的先例）。
- **待办完成数口径**：按设计风险项 1 的默认方案取 `date(substr(updated_at,1,10))` 近似完成日（complete/confirm 均重写 `updated_at`），±8h 时区边界误差接受，测试用两种历史时间格式（ISO 与 `YYYY-MM-DD HH:MM:SS`）+ 两周各自的周一/周日边界行固化。
- **今日焦点计数上限**：到点待办的 overdue/today 计数在 `LIMIT 8` 窗口内切分（展示用途，与设计 §3.3 SQL 一致），不做全表 COUNT。
- **联动预填一次性**：draft 在页面挂载时经 ref 捕获一次，URL 参数随即 `replace` 清除；prop 变 null 不影响已打开的抽屉与区域警示（区域警示随行程自然周存续，抽屉预填在关闭/保存/手工新建时清空）。
- **新招标锚点**：沿用晨报"昨日 09:00 Asia/Shanghai"锚（设计开放问题 4 默认项），tender 采集未启用时空态友好显示"近 24 小时暂无新招标"。
