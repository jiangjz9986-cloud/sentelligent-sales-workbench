## 关键裁定与设计偏差

- **发票"替票"映射决策**：用户手工表中的"替票"概念在系统中已有同名既有状态 `substitute_invoice`（触发条件：确认的发票匹配 `matchMethod=rule_candidate`，或附件 kind=substitute），导出词表 `电子 / 替票 / 无票确认 / 待补` 全部沿用 `travelExpenseExport.js` 既有 `EXPENSE_INVOICE_STATE_LABELS`，**无新造词、无界面新词**；"替票合计金额"= 清单内费用的已确认 rule_candidate 匹配分摊额合计（既有 `buildExpenseListTotals` 口径不变）。
- **XLSX 嵌图实现程度**：完整实现、非降级。付款记录列内嵌真实 JPEG 图片沿用既有无依赖手工 OOXML zip 组装（stored ZIP + drawing1.xml oneCellAnchor + media/*.jpeg，缺图 fail-closed 拒绝生成）；本版新增合并标题行后所有锚点/合并区/冻结窗格顺移一行并有断言覆盖。
- **标题日期范围**：取清单内费用实际发生日期的最小/最大值（对齐用户手工表 8.17-8.21 为工作日实况的语义），空清单回落自然周起止；城市列表取本周负责区域 profile 的全部城市（顿号连接），未设置区域时标题退化为 `M.D-M.D出差费用清单`。
- **备注列拼装**：按任务书取系统现有 `purpose`+`notes` 字段（"；"连接、去重、任一为空自动省略），推翻旧注释"备注只取 notes"的口径；用途列保持类别词（餐费/住宿/交通/招待/其他）。
- **"账本视图"对齐范围的解释**：账本是按日运营视图（时间/类型/分类/金额/凭证/发票/操作），不能逐字复制 7 列清单；本版使其与手工版式精神一致——凭证列成为最宽列之一且缩略图肉眼可辨、发票状态词与导出同表、合计条保留可报销/垫付合计；7 列版式的逐字对齐落在打印预览与 XLSX 两个输出面。
- **待确认行去向**：移除只读卡后，账本内小小待确认行保留（含日签 `N 待` 徽标与 12 秒轮询同步），行内动作"核对入账"改为禁用态"微信中确认"指引（网页无确认动作，微信为唯一确认端）。
- **打印分页容量**：凭证图放大至与 XLSX 内嵌图同物理尺寸（约 2 英寸宽）后，A4 纵向每页凭证行数 9→6（`rowsPerPage=6`），分页器本身参数化、既有分页测试全部保留。
