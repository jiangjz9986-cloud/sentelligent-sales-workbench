# Sentelligent v0.4.2

This patch release closes two production-preflight boundary gaps found after the v0.4.1 release rehearsal. It does not change the travel-reimbursement API, database migrations, or user-facing workflow.

## Changes

- Require `sentelligent-frontend.service` to use exactly `/opt/sentelligent-sales-workbench/config/frontend.env` and reject lookalike paths outside the project configuration root.
- Keep schema-3 release contents fully inventory-bound.
- For the explicitly scoped schema-2 current-release compatibility path, preserve an exact archive inventory and reject every unverified dependency or other additional file.
- Require legacy and candidate releases to be root-owned immutable trees, and reject any candidate that was not already frozen before complete manifest hash verification so the runtime identity cannot replace content in between.
- Retain the existing current-release, service-command, host, database, and protected-service identity gates.
- Add red-green regression coverage for the deployed dependency layout and canonical frontend environment path.

## Deployment boundary

- The production cutover may stop or restart only `sentelligent-backend.service`, `sentelligent-frontend.service`, and `sentelligent-weixin-agent.service`.
- Shared Caddy, Qingyang, account-vault, Mihomo, and port `8797` remain protected and must be unchanged before and after cutover.
- Cutover still requires a fresh exact `24/24` preflight report, an integrity-checked SQLite backup, the immutable GitHub Release archive, `25/25` HTTPS smoke with clean cleanup, and real-browser acceptance.

## Evidence policy

Record only non-secret commit, tag, archive digest, release/evidence paths, timestamps, check counts, and protected-state fingerprints. Never record tokens, passwords, cookies, private keys, environment-file contents, database contents, or business attachments in Git or chat.
