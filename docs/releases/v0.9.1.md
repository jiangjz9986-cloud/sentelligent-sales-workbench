## 关键裁定与设计偏差

- **审计吊销计数键改名**：任务书写 `after={sessionsRevoked}`，但 `auditRepository` 敏感键正则会剔除一切含 `session` 的键名（哈希红线机制），实施改用 `revokedCount`（HTTP 响应仍返回 `revokedSessions`，语义不变）。
- **设计文档 secret 扫描 finding 归零（v0.9.0 遗留③）**：任务书 §1.1 示例代码里"哈希敏感键: 同名裸值"的写法（.md 属 bare-assignment 扫描面）触发 `API key assignment`；文档与真实迁移同步把局部变量改名 `envHash`（7 字符，低于 credential-like 阈值），工作树扫描 findings=[]。
- **三个既有测试 harness 随门禁升级**：`hospital-tender-scheduler-api`/`hospital-tender-internal-api` 原用 dev 明文密码（不建 users 行 → 回退轨=member → 新门禁 403），改为 scrypt 哈希让启动兜底种子建出 admin 行；`settings-config-api` 的账号 `settings-owner` 含连字符不合 `^[a-z0-9]{2,32}$`，改为 `settingsowner`。dev 明文兼容轨语义保留：能登录、但无 users 行即无管理面（member 回退语义）。
- **视觉走查桩补 role**：`visual-rhythm.test.mjs` 的会话桩加 `role: 'admin'`——v0.9.1 起系统配置子导航按角色过滤，member 桩点不到微信绑定子页。
- **module-coverage 审定清单 +1**：settings 组子页清单加入 `settings-users`（v0.7.1 教训的注册点守护测试按新审定基线更新）。
- 前端正式交付文案禁词（"后端"）在 App.jsx 新注释中触发 `formal-ui-copy` 门禁，改写为"服务端"。
