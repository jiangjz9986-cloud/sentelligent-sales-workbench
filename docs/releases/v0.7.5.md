# 森特智行 v0.7.5 智能待办 + 到点提醒

## 目标

- 微信里一句话建待办："提醒我明天上午十点给王工送方案"→ 解析时间/优先级/对象 → 轻确认写入 → 到点小小绑定私聊推送提醒（v0.7 全能助手系列第六步，总蓝图 F 阶段）。
- 补齐 action_items 的 owner 归属缺口：独立待办（不挂客户/商机）首次对小小可见。

## 主要变更

见 `CHANGELOG.md` [0.7.5] 条目。要点：五工具（create/list/complete/defer/delete，R1 轻确认×3 + R0 + R2 六位码）、`spokenTime.js` 未来向时间解析、迁移 0028（owner/remind_at/reminded_at + 部分索引 + 存量回填）、`actionItemStore` 共享写路径、60s 轻循环调度器（表即队列、双幂等、离线补发、过期标注）、outbox 新 kind=`action_reminder`、管理端点与两个环境变量。

## 关键裁定（设计文档 2026-08-28-v074-todo-agent-design.md）

- 到点提醒**不受 9–20 免打扰窗约束**（用户自设闹钟语义）；柔性兜底=夜间时刻预览卡提示 + 无时刻默认 09:00。
- 不复制招标三表状态机：action_items 表即队列，零新状态表；outbox 唯一键 + reminded_at 双幂等。
- 顺延归一为 pending（deferred 留给 Web 手工语义）；单次提醒不重复催办（逾期汇总由 v0.7.7 晨报承接）。
- 建待办 id=pending actionId（重放安全）；`source_record_id` 保持 NULL 不占用深写回幂等键。

## 实施说明

- 主会话亲自实施（子代理因账单额度不可用）；迁移 0028 三件套复用了此前子代理死前的起步产出（核对后原样采用）。
- 与设计的偏差：① 提醒卡/预览卡/回执卡全部采用 v0.7.4 的 weixinCard 统一版式（设计成稿早于卡片统一）；② 群聊拒绝实测由 HTTP 边界（weixinAllowGroups=false）先行 403 拦截，provider 写门作为纵深防御保留；③ `spokenTime` 常量命名避开 `*_TOKEN = "…"` 形态（密钥扫描器误报，改名 `*_WORD_SOURCE`）。
