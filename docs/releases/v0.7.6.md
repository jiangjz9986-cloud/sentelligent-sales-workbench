# 森特智行 v0.7.6 小小·商机 agent

## 目标

- 微信里查/改商机：列表与详情免确认，改阶段与下一步轻确认（回复"确认"），改金额/名称/风险与新建走六位码，删除六位码软删除；阶段前进确认后自动附带销售决策阶段升级检查（v0.7 全能助手系列第七步，总蓝图 G 阶段）。
- 核销 v0.7.2 登记的技术债：画像句式排除名单重排，"XX项目/商机什么情况"从落 unknown 改为转发商机详情。

## 主要变更

见 `CHANGELOG.md` [0.7.6] 条目。要点：六工具（list/detail-既有/update-stage/update-next/update/create/delete，R0×2 + R1 轻确认×2 + R2 六位码×2 + R3 六位码）、阶段词表后端镜像（`stageVocabulary.js`）、8 秒 race 预算的同步阶段升级检查、两级消歧坍缩（LIKE 商机名 OR 客户名 + 尾 6 位回指）、快照/适配器 version 投影与 expectedVersion 钉版、商机写路径 store 化（`opportunityStore.js`）、审计零新词、一个环境变量（`OPPORTUNITY_STAGE_REVIEW_BUDGET_MS`）。

## 关键裁定（设计文档 2026-08-28-v075-opportunity-agent-design.md）

- 改阶段 R1 轻确认（单字段完全可逆、看板即时可见、最高频动作），改金额 R2 六位码（进入决策分析输入与漏斗/周报口径，错误隐性成本高）；建档 R2、删档 R3 与客户先例对齐。
- 联动裁定同步附带 + 时间预算（默认 8 秒），不做 outbox 异步推送、不做配置开关；决策模型超时下限 120s 在外层 race 解决，被放弃的 promise 后台完成并持久化 run，可用"项目分析"拉取。
- 仅前进方向触发（词表内且目标非"暂停观察"）；回退/词表外/暂停在回执附一行手动提示代替。
- 建商机客户必须唯一命中（customer_id NOT NULL），不做"多命中默认取第一个"；同名查重仅限同客户（跨客户同名是合法业务）。

## 实施说明（与设计的偏差）

- ① 工具命名：设计中的 `opportunity.updateStage/updateNext` 驼峰名不满足 `contracts.js` 的 `TOOL_IDENTIFIER` 小写合同，落地为 `opportunity.update-stage`/`opportunity.update-next`。
- ② 消息卡：设计对话样例成稿早于 v0.7.4 卡片统一，全部预览卡/回执卡/候选卡按 weixinCard 统一版式落地（【标题】+ 标签行 + 一句操作提示），不出现 UUID/乐观锁版本号，编号用尾 6 位。
- ③ 审计 stageReview 值域：设计列 attached/timeout/failed/skipped_*，但审计必须与业务写同事务原子提交，而联动结果在事务外的 race 之后才可知——审计记录触发决策（triggered/skipped_backward/skipped_unknown_stage/skipped_pause，另有防御性 skipped_same），attached/timeout/failed 结果记录在工具运行输出（assistant_tool_runs/pending action result）与回执文本，可观测性不损失。
- ④ `opportunity.list` 的 query 参数放宽为可选："商机列表"两字列出全部 owner 可见商机（≤8 条），设计的"主语与列表词至少一个存在"约束在 router 层实现，裸"商机"两字 clarify 引导。
- ⑤ 群聊拒绝实测由 HTTP 边界（weixinAllowGroups=false）先行 403 拦截，provider 写门与 list handler 的 direct 检查作为纵深防御保留（v0.7.5 同款）。
- ⑥ 行为变更（设计 6.2 预告并固化回归）：宽"推进到"正则使"会议推进到下周"等非商机主语从拜访兜底改为商机 not_found 自澄清卡；商机查询组对含拜访词干的叙事主语让路拜访兜底（"…拜访了X聊了聊商机"仍是拜访记录）。
- ⑦ `countOpportunityReferences` 中 solution_drafts 不带 deleted_at 过滤——该表自迁移 0002 起就没有软删列（版本列有），按现状计数。
