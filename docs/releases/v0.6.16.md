# 森特智行 v0.6.16 微信入站游标阻塞热修

## 问题

生产微信 worker 从持久游标恢复后，同批第一条历史文本事件已由后端完成并返回 HTTP 200，但旧上下文下的微信回复投递失败。vendored SDK 把“Agent 处理失败”和“回复发送失败”放在同一个异常分支，因而不提交下一游标并每约两秒重试整批；同批后一张付款图片始终不能进入后端。

## 修复合同

- `agent.chat` 的瞬态失败继续保留旧游标并重试，防止未完成业务事件丢失。
- `agent.chat` 已成功而只有回复投递失败时，记录不含正文和凭据的 `category=delivery status=failed`，把当前入站事件视为已处理并继续同批下一条。
- 同一业务事件不因微信回复失败而重复执行；整批完成后才保存 provider 返回的下一游标。
- 不删除或重建微信 session、sync cursor、数据库事件、记账草稿、outbox、付款凭证或发票记录。

## 边界

- 基线为生产 `v0.6.15` exact commit `212f1cf4f351661fd5d226006999d8247a2e8bc2`。
- 修改范围仅包含 vendored 微信 SDK 行为、针对性回归测试、版本和发布说明。
- vendored SDK 版本升至 `0.5.0-sentelligent.6`；公共类型不变。
- 无数据库迁移，不改变微信记账、自然语言确认、报销、借款或发票匹配业务合同。
- 不接入“整理报销”会话的开发内容；不写入 GitHub。

## 验收

- 保留原有“Agent 首次失败时旧游标不推进、成功重试后才推进”测试。
- 新增“第一条 durable result 回复失败、第二条仍处理且各仅一次”的同批测试。
- 发布前运行后端全量、部署门禁、vendored provenance、历史密钥扫描和差异检查。
- 生产切换前备份数据库与完整微信会话；切换后验证旧回复失败被隔离、当前图片进入后端、游标更新、服务健康和数据库完整性。
