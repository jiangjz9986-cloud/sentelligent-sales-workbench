## 关键裁定与设计偏差

- **孤儿测试修复方向**：`HospitalTenderPage.test.mjs` 挂在旧断言 `setCustomerFilter(customerId)`/`useState(customerId)` 上——组件在演进中改为 `customerId ?? ""` 防御写法（语义同、增加空值兜底）。按"守护意图不变"原则更新断言匹配现实写法，而非改组件迁就测试。
- **A 类 28 个分支含 `local/production`**：清册 §1.3 计 28 含"需确认后的 local/production"，§1.5 又将其列入需确认 32。按任务书"A 类 28 个 `git branch -d`（验证包含性）"执行：`local/production`（6b2142f = v0.6.25）实证 CONTAINED，生产身份以服务器 release 目录与 tag 为准，该分支删除（archive tag 兜底）；剩余需确认 31 个仅列清单未删。
- **`git branch -d` 的校验基准**：主 checkout 挂在 `codex/settings-config-pushplus`（非主线），在主仓库根执行 `-d` 会对错误的 HEAD 校验包含性而拒删。对策：从主线工作树（HEAD=`local/v0627-feature-closeout-20260827`）内执行 `-d`，包含性校验仍由 git 本身把关。
- **脏 worktree 占用 A 类分支**：两个 expense-ledger 脏 worktree（48/1 项改动，按任务书跳过删除）占用两个 A 类分支。以 `git -C <脏树> switch --detach` 摘 HEAD（同 commit、工作区文件一字不动、脏改动保留待人工过目）后 `-d` 通过。
- **守护测试取源改造范围超出清册**：清册记载唯一硬约束为 `workbenchState.test.js`；实扫发现 v0.8.1–0.8.3 期间新增了 8 个读 pages.jsx 源文本的 scripts 测试（contract/copy/controls/forms/readonly/list-actions/modules/sales-decision-page）。统一新增 `scripts/pages-source.mjs` helper 聚合读取桶文件 + `pages/` 目录，全部断言一字不动；`salesDataImports` 升级为全局匹配（聚合文本多条 import 逐条检查，防守护强度衰减）。
- **拆分粒度**：13 文件按清册 §3.2 执行，v0.8.3 新增的 TodayFocusCard/WeeklyTrendCard/趋势 helper 归入 `OverviewPage.jsx`；`SummaryLine` 留在 QuickRecordPage 并保持桶文件导出（"保导出面"优先于清册的"顺带收敛"建议）；每文件 import 集按引用实证计算，6 个死 import（BarChart3/ClipboardList/Lightbulb/LineChart/Target/ExtractCard）不再携带。
- **差旅删除入口位置**：删除按钮只出现在正式费用行（`item.kind==="expense" && item.formal`）；待确认行的删除属微信确认流职责、借款行走结算子卡，均不出删除入口。confirm 文案沿用死代码中的既有文案（`确认删除“<事由>”？`）。
- **outbox 清账语义**：`outboxRepository` 无删除/核销合同（`failed` 即终态、`requeueFailed` 仅限 retryable 码、`closePending` 是标记非删除），按任务书走"生产只读确认内容 → SQL 删除 + `audit_logs` 留痕"，于部署窗口执行（记录见下方"生产技术债清账"）。
