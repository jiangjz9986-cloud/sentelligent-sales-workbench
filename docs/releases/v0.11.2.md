## 本次实现

### 1. 滚轮与滚动根

- 修复受限 workspace 中包装层按内容高度撑开、导致 `.content` 没有垂直滚动范围的问题。
- 让 `PullToRefresh` 填满受限 workspace 行并保持 flex 约束；页面级垂直滚动仍由 `.content` 承担。
- 覆盖桌面 wheel、移动布局、页面滚动根、嵌套面板顶部/底部滚动链和关闭弹窗后的滚动恢复。

### 2. 主动助手稳定性

- 持久化建议的修订、刷新回读、跨入口身份和 owner 隔离保持一致。
- 覆盖后台扫描、周期续扫、重启恢复、租约、通知去重、缓存/额度和确定性 fallback。
- action/risk 写回继续经过预览、显式确认、幂等、版本冲突和审计边界。
- 主动助手控件的桌面/窄屏触达尺寸通过契约测试。

### 3. 客户详情与验收

- 客户详情展示版本、同步摘要、别名、标签、创建时间和更新时间。
- 可识别的 SQLite 时间字符串和 ISO 时间统一按 `Asia/Shanghai` 展示；非法或空值安全回退为未记录。
- 长名称、摘要、标签和元数据不会造成页面或详情区域横向溢出。
- 通过隔离数据库中的认证 `POST /api/customers` 创建临时客户，验收列表、别名搜索、详情、编辑取消、编辑保存、版本递增、删除取消和响应式布局。

### 4. 证据与门禁

- 浏览器证据报告记录源码 commit、工作树状态、构建身份、运行时间、浏览器版本、视口和失败响应。
- evidence 网络限制支持显式前端 origin 与隔离后端 origin，不允许其他外部流量。
- 主动助手面板、客户元数据、浏览器证据身份、滚轮专项和客户验收已接入相应常规命令。

## 明确不包含

### CSV/XLSX 批量导入

当前产品没有 CSV/XLSX 上传 UI，也没有批量导入 API。本版本的客户验收证明的是“客户通过现有认证 API 创建后，页面和持久化链路可用”，不是文件导入能力。批量导入需单独设计字段映射、查重、预览确认、事务回滚、审计和大文件安全边界。

### 主动助手 action 字段契约扩展

本版本不改变 `action_items` 数据库契约。主动建议确认写回时，action 的优先级使用现有默认值“中”，负责人使用当前 owner；建议预览中的 `assignee`、`dueDate`、`priority`、`expectedResult` 等人工字段不应被描述为已经完整落入业务 action 表。后续如需完整写回，先冻结共享契约、迁移方案、冲突语义和回滚策略，再单独发布。

### 真实生产闭环

本地隔离回归不等于真实模型质量、微信客户端接收、PushPlus 接收/已读、客户级主动扫描或医院招标同步 bridge 已完成。没有新的生产授权前，不执行 SSH 写操作、迁移、服务重启或真实通知发送。

## 可复现验证

最终冻结后应在干净工作树重新运行以下门禁；报告中的 exact commit 必须与最终候选一致：

```bash
npm run test:deploy
npm --prefix backend test
CHROME_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
SENT_ZX_INTEGRATION_RUNTIME=native \
npm --prefix outputs/product-design-prototype run qa:local
CHROME_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
SENT_ZX_INTEGRATION_RUNTIME=native \
npm --prefix outputs/product-design-prototype run qa:integration
npm --prefix outputs/product-design-prototype run qa:webkit
npm --prefix backend audit --omit=dev --json
npm --prefix outputs/product-design-prototype audit --omit=dev --json
git diff --check
```

专项 evidence 入口：

- `.runtime/browser-evidence/v0112/scroll-wheel/`
- `.runtime/browser-evidence/v0112/customer-api-acceptance/`
- `.runtime/v0112-closeout/restore-rehearsal-report.json`
- `.runtime/v0112-closeout/production-readonly.json`

WebKit 的 iPhone 尺寸检查是浏览器等价验证，不是 iPhone 真机验收；桌面录音、真机麦克风和服务端 ASR 不计入本版本通过项。

## 放行条件

1. 最终工作树干净，版本字段统一为 `0.11.2`，release note、CHANGELOG 和 evidence 指向同一候选身份。
2. 根发布测试、backend 全量测试、frontend local/integration/WebKit、依赖审计和 `git diff --check` 无非预期失败。
3. 滚轮和客户验收报告为 `passed`，且报告 source commit 等于最终候选 exact commit。
4. 恢复演练报告的 source commit 更新为最终候选；备份原件未被修改，迁移重复执行幂等，SQLite 完整性和外键检查通过。
5. 客户原始清单对账、真实模型/外送、CSV/XLSX 导入和生产切换状态在交付说明中单独标记，不以空库或模拟结果替代。

## 后续路线

1. `v0.12.0`：客户级主动助手 subject、真实模型和通知验收、医院招标唯一事实源 bridge。
2. 独立功能版：CSV/XLSX 客户批量导入，先取得脱敏样表并冻结导入契约。
3. ASR、多人权限/审批和其他延期项按独立验收条件排期，不阻塞本维护候选。
