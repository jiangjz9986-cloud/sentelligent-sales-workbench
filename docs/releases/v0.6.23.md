# 森特智行 v0.6.23 小小餐饮时段自动分类

## 目标

- 用户继续只需在本人微信私聊中向小小发送付款凭证；图片/PDF 识别结果只生成待确认草稿，不绕过人工确认。
- 早餐、午餐、晚餐在固定消息中统一显示父类“餐饮”，餐次进入内部子类和自动备注。
- 自动备注使用发生日期的月日、owner/date 行程中的唯一出差区域和餐次，例如 `8.25济南午餐`。

## 分类合同

| 上海付款时间 | 单笔金额 | 默认餐次 |
| --- | ---: | --- |
| `04:00–10:59` | `0.01–40.00` 元 | 早餐 |
| `11:00–15:59` | `0.01–40.00` 元 | 午餐 |
| `17:00–23:59` | `0.01–40.00` 元 | 晚餐 |

- `16:00–16:59` 和 `00:00–03:59` 不按时钟猜餐次。
- 同一截图中识别出的多笔付款由视觉模型输出最多 20 个严格结构化交易，再逐笔生成草稿；各笔保留自己的金额、日期、支付时间、商户和支付方式。单一详情页的原价、优惠、合计与实付不会拆成多笔，同一附件重发固定复用首次内容寻址结果。
- 超过 40 元时，只有餐厅、饭店、烧烤、快餐等餐饮商户，或明确的多人出差用餐语义，才按付款时段推断餐次；单人场景不明的大额用餐保留复核提示。
- 明确的客户招待/宴请、住宿、交通和汽车维保语义优先于餐饮时钟；无法判断的商户保持“其他”，不强行归类。

## 备注与修改

- 行程区域只读取同一 owner、同一发生日期、未删除且状态为 planned/completed 的行程；多城市、超过有界查询数量或没有唯一城市时不猜测，并提示出差区域待确认。
- 商户名称继续保存在商户字段，不作为普通备注；只有餐饮草稿自动生成餐次备注。
- 自动备注保存受限的来源元数据。用户修改金额、支付时间、商户或用途时重新执行餐饮边界，修改日期时重新读取对应日期的行程区域，修改早餐/午餐/晚餐时同步重算餐次，修改为非餐饮类别时清空自动备注；用户明确修改类别或备注后尊重人工结果，不再用旧 OCR 内容覆盖。
- 金额修正必须至少为 0.01 元；`0 元` 保持澄清且不旋转草稿版本、不新增 outbox。区域只接受明确字段、句首或分隔后的“到/赴/前往/去 + 城市 + 出差/差旅”，普通叙述失败关闭到唯一行程城市。
- 修复 `修改费用类别为交通` 等回复被前缀“费用”误当成金额修改的问题；修订后必须先收到最新版本草稿，旧引用不能确认新版本。

## 保留边界

- 内部继续使用 `category=餐饮` 与 `subcategory=早餐|午餐|晚餐`，确认后映射到现有正式费用类别；没有数据库迁移。
- 汽车维保仍在快捷记账三级菜单与草稿中保留“维修/保养”粒度；既有正式报销表没有 `maintenance` 枚举，确认时继续按兼容合同写为 `other`，本版不扩展数据库枚举。
- 支出可报销金额继续等于消费金额；无借款时仍为个人垫付，借款到账收入和自然周分配逻辑不变。
- 图片和 PDF 使用 `deepseek-v4-flash-vision-exp`；其他模型任务使用 `deepseek-v4-flash`。
- 本版不清理微信 session、游标、历史消息、待确认草稿、outbox 或报销数据，不同步 GitHub。

## 验收

- 覆盖时间与金额边界、手机状态栏与付款时间冲突、低额非餐饮强语义、大额商户/多人场景、行程 owner/date/状态/删除/多城市/上限隔离和多笔拆分。
- 覆盖自动备注在日期、餐次、父类修改后的重算/清空，以及最终确认写入正式费用表。
- 发布仍需通过后端全量测试、部署/发布脚本、历史密钥扫描、前端本地/集成/WebKit 门禁和 fresh 生产 preflight、cutover、postflight、HTTPS smoke。
