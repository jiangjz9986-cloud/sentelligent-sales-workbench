# 森特智行 v0.6.22 微信单次回执兼容热修

## 问题

- v0.6.21 已兼容 HTTP 2xx 空正文，但真实微信发送接口本次返回 HTTP 200 和仅含 `message_id` 的 JSON 对象。
- 旧校验器把这个已接受回执视为未知非空响应，导致 outbox 把已投递消息重新排队，界面可能看到重复消息。

## 修复合同

- 仅当 HTTP 成功且原始 JSON 对象只有一个 `message_id` 字段，并且该值是 1 至 20 位、未超过无符号 64 位上限的正整数时，才把它视为成功回执。
- 继续接受空/空白正文、空对象，以及顶层或 `base_resp` 中全部为数值零的 `ret`/`errcode`。
- 空 `message_id`、非正整数、附加未知字段、畸形 JSON、非对象和任何显式非零状态继续失败关闭。
- SDK 不记录 provider 正文或消息标识；测试只使用合成标识。

## 保留行为

- 新付款凭证备注默认空，商户与用途保持独立；用户的自然语言修改同步草稿行、分析快照和下一版确认消息。
- 图片与 PDF 使用 `deepseek-v4-flash-vision-exp`；其他模型任务使用 `deepseek-v4-flash`。
- 人工确认门禁保持不变；本版无数据库迁移，不同步 GitHub。

## 验收

- vendored SDK 覆盖 19 位原始数字 `message_id`、空正文、零状态、显式拒绝、字符串/空/非正/非整数/超界标识、重复键、混合未知字段和畸形响应。
- 生产 outbox 的 v2 草稿只允许从 `queued` 变为 `sent` 一次，`attempt_count` 不再增加；数据库保持 `quick_check=ok`、外键异常为 0。
