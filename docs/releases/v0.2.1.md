## 根因

WSL 辅助脚本使用宿主平台的 `path.resolve()` 处理 Windows 绝对路径。Linux runner 不把 `C:/...` 识别为本机绝对路径，因而将其错误解析为 `<cwd>/C:/...`，造成 6 项跨平台路径测试失败，并阻断 `v0.2.0` Release workflow。

## 热修复内容

- 增加跨宿主工作区路径解析：带盘符的 Windows 绝对路径使用 `path.win32` 规范化，POSIX 绝对路径使用 `path.posix` 规范化，相对路径才交给宿主平台 `path.resolve()`。
- 增加跨宿主路径拼接：Windows 和 POSIX 绝对路径分别使用对应平台的 `join()`，避免 Linux 路径被误转为反斜杠形式。
- UNC 网络共享和 Windows 根相对工作区路径不能可靠转换为 WSL 工作目录，现改为明确失败并提示映射盘符或传入已挂载的 POSIX 路径。
- 本地开发、WSL 后端和 WSL 全栈配置入口统一采用同一套路径解析规则。
- PR CI 的根测试门禁与 Release workflow 对齐为 `node --test scripts/*.test.mjs`，确保发布工具、生产预检、秘密扫描和 WSL 辅助脚本在 Linux runner 上完整执行，避免只在打标签后暴露回归。
- 根凭据扫描命令显式传入 `--history`，即使扫描器未来修改默认值，PR CI 仍与标签发布保持完整历史范围。
- 根项目、后端和前端正式版本统一升级为 `0.2.1`。
