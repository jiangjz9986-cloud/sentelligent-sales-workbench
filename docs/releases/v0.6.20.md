# 森特智行 v0.6.20 生产 PDF 视觉渲染兼容热修

## 问题

`v0.6.19` 已把图片和 PDF 路由到 `deepseek-v4-flash-vision-exp`，但生产服务器的 Poppler 0.26.5 不支持较新版本才提供的 `pdftoppm -jpegopt` 参数。真实 PDF 在提交视觉模型之前即渲染失败。

## 修复合同

- PDF 仍使用受控 `/usr/bin/pdftoppm`，最多渲染四页、最长边 2048 像素，并验证每页 JPEG 魔数、单页和总字节上限。
- 删除 `-jpegopt quality=88`，只使用生产 Poppler 0.26.5 已验证支持的 `-f`、`-l`、`-scale-to` 和 `-jpeg` 参数。
- 图片与渲染后的 PDF 继续只提交 `deepseek-v4-flash-vision-exp`；普通文字模型任务继续使用 `deepseek-v4-flash`。
- 微信 provider 回执兼容、稳定 outbox `clientId`、固定待确认消息和人工确认边界保持 `v0.6.19` 行为。

## 验收与边界

- 单元测试锁定完整 `pdftoppm` 参数数组，并明确禁止 `-jpegopt`。
- 生产使用合成单页 PDF 完成 `pdftoppm` 渲染和官方视觉模型字段提取，不写入业务数据库、不发送微信消息。
- 无数据库迁移；只切换 backend、frontend 和 weixin-agent，不重启共享 Caddy。
- 按项目所有者授权使用本地 exact-commit 不可变制品直接发布生产，不同步 GitHub。
