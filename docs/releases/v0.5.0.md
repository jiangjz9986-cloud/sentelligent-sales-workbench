# Sentelligent v0.5.0

## Scope

v0.5.0 turns the existing WeChat Clawbot bridge into a persistent assistant runtime. It keeps conversations and draft parts in SQLite, accepts replayable inbound events, and exposes a bounded first slice of assistant agents for visits, customer search, sales-week previews, reimbursement summaries, payment proofs, and invoices.

The assistant remains a personal workbench. Natural-week reimbursement behavior, original PDF/image bytes, manual review, and the existing iCost and invoice boundaries are preserved. Company over-limit rules and automatic financial writeback are not enabled by this release.

## Safety guarantees

- Tool selection is deterministic and allowlisted. The model cannot provide identity, owner, transport, filesystem, shell, database, or arbitrary path values.
- Risky writes require a confirmation tied to the stored tool, validated arguments, owner, channel, and conversation. New confirmation text cannot replace that plan.
- A one-time execution lease and a stable action-scoped tool-run identity protect concurrent requests and the crash window between a business write and the durable result.
- Expired leases can be reclaimed. If a confirmation code is lost after a crash, a new scoped event can rotate the code; the previous code is invalidated and only its HMAC is retained.
- Quick-record reads and writes are owner-scoped. Migration `0012_assistant_owner_and_plan_digest` backfills verifiable ownership and labels unverifiable historical rows `legacy`.
- Production requires independent high-entropy machine and confirmation secrets. Non-loopback remote Clawbot backends require HTTPS.

## Deployment boundary

This is a GitHub development candidate only. Production remains on v0.4.4 until a separately authorized release run completes a fresh database backup and restore rehearsal, immutable package verification, production preflight, controlled service cutover, post-cutover health checks, and real WeChat-device plus browser acceptance. The production-only confirmation secret must be installed out of band and must never appear in source, logs, command arguments, Git, or chat.
