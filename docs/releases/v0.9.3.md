## 关键裁定与设计偏差

- **任务书三条新裁定落地**：一账号至多一条 active 绑定（partial UNIQUE 索引强制）；绑定码新建绑定 `financial_enabled=0` 默认关（admin Web 显式开启，财务写入最高风险面显式授权）；`digest_enabled` 语义=主动推送总闸（晨报+周五收尾+待办提醒+招标推送，绑定默认开；告警除外——告警目标=active admin 绑定，无视 digest 总闸）。
- **绑定表本身即白名单（D2 落地）**：不建独立 allowlist 表；`WEIXIN_ALLOWED_SENDER_IDS` 的 sender 过滤分支从 `assertWeixinSenderAllowed` 中退役（函数更名 `assertWeixinGroupAllowed`，群规则原样保留）；worker `authorizeInbound` 随之放行全部私聊（未绑定者由后端入口闸回固定绑定引导），群闸本地保留。
- **未绑定拒答回 200 而非 403**：`{status:"denied", text:"您尚未绑定工作台账号，请联系管理员获取绑定码后发送：绑定 123456"}`——200 保证 worker 把引导文案带回用户（403 会被 worker 当错误吞掉）。拒答不入编排、不落 assistant_inbound_events、不写 blob（测试以表计数钉死）。
- **绑定语义收敛（超出任务书字面处逐条声明）**：
  - 绑定意图只在私聊识别（群聊里发绑定码一律固定拒答，防码在群内泄露被围观者消费）；绑定控制词（解绑等）同样仅私聊生效，群聊消息走正常编排由财务闸拒。
  - redeem+users active 校验+bind 包在同一事务：绑定失败（如赛跑中账号被占）回滚码消耗；已停用账号的码兑换按 invalid 拒。
  - 换绑冲突（码有效但账号已在别处 active 绑定）回专用文案并计一次限流失败，审计 reason 归入 invalid 词表。
  - `ensureBootstrapBinding` 只插不改且 **admin 显式停用过的 sender 行绝不复活**（表中存在任何该 sender 行即跳过）。
- **绑定 sender 的私聊会话恒为 shortcut 会话**：conversationScope 判定从"sender==配置 sender ∧ owner==配置 owner"改为"绑定存在 ∧ 私聊"——provider 会话号不再切分同一 sender 的私聊会话（生产语义与 v0.9.2 的 jiangjz 实况一致）；泛型 `weixin:conversation:v1:` 分支仅余群聊（生产不可达，保留作防御）。既有"同 sender 不同会话号"隔离用例改造为"他人绑定 sender/未绑定 sender 不可确认"矩阵。
- **financialScope 增加 runtime.enabled 条件**（任务书 §3.1 原文）：`chatType==="direct" ∧ binding.financial_enabled ∧ runtime.enabled`。若生产曾在 confirmation 关闭时依赖财务面（现产恒开启），此为收紧；测试 harness 相应补开关。
- **digest `runOnce/runManual` 返回形状升级**（任务书点名 additive）：runOnce 的 daily/friday 改为逐 owner 数组；runManual 返回 `{status 聚合, digestDate, deliveries[]}`；`markers()` 保留 daily/friday 顶层（enqueued=全部目标已入队）并新增 `deliveries[]`。前端无消费方（rg 核实），`POST /api/digest/run` 为 admin 运维端点，形状变化随 release 文档声明。
- **opsAlert 多目标响应聚合**：item 取首target行（replayed=全部目标均重放才 true），HTTP 契约字段名不变。
- **招标 unrouted 语义**：无路由公告（匹配客户的 owner 均无 active∧digest 绑定）→ 投 digest-enabled 的 admin 绑定 → 无则 PushPlus → 再无（或 PushPlus 抛错）→ 审计 `hospital_tender.push.unrouted` 计数后视为已处理，维持 `notified === newHighNotices.length` 的调度器重试契约（公告数据仍在库，Web 可见）。
- **顺手修复（v0.9.2 验收观察项）**：快速记录 confirm 的模型幻觉 id 白名单校验——insight 给出的 customerId/opportunityId 仅在库内真实存在（owner 归属内）才作为确认目标，否则按"未匹配"回退记录原值；存量行自身的失效引用仍按原语义 422。
- **secret 扫描自查**：三个新测试文件的机器令牌字面量初值含 `binding-flow/matrix/bindings` 等词表外词被两级扫描命中，改为白名单形态（`weixin-test-machine-token`/`weixin-scope-test-machine-token`/`weixin-admin-test-machine-token`）并 amend 红测试提交（本会话内本地未推送提交，v0.9.2 同款处置）；冻结树两级扫描 findings=[]。
- **CRLF 行尾卫生**：本版编辑到的 CRLF 历史文件（digestScheduler/reminderScheduler/UserManagementPage 及四个测试文件）随编辑归一 LF；未触碰的历史 CR 文件照旧不动（v1.0.0-rc 统一清理），`git diff --check` 干净。
