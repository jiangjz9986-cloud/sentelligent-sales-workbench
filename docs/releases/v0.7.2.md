# 森特智行 v0.7.2 小小·客户画像 agent

## 目标

- 把客户档案的查/增/改/删收进微信助手"小小"：查询免确认，新增/修改/删除走六位码确认（v0.7 全能助手系列第三步，总蓝图 D 阶段）。
- 复用 `customerAssistantAdapter` 的 change_preview 能力：确认前先出客户消歧与逐字段 before/after 预览卡，把"确认的就是执行的"钉进持久化计划。

## 主要变更

- 三个客户写工具注册进编排器：`customer.create`（R2/explicit_code）、`customer.update`（R2/explicit_code）、`customer.delete`（R3/explicit_code，软删除）；查询类维持 R0 免确认。写操作仅限与小小绑定的私聊（`chatType!=="direct"` fail-closed），owner 由 `businessOwnerResolver` 精确解析，参数合同继续禁止 owner/actor 等键。
- 编排器新增可选 `pendingPreviewProviders` 钩子（`server.js` 注入，缺省不影响任何现有确认流）：建 pending action 前完成客户消歧（唯一命中→预览卡；多命中→候选澄清；零命中→引导建档）、建档重名保护、无变化短路（"内容与现有档案一致"）；规范化参数 + 乐观锁 `expectedVersion` 写入 `payload.plan`，预览摘要存 `payload.preview` 并随"重发确认码"重发。明文码与预览卡只出现在同步 live 响应，事件存档仍为占位文本。
- `handlePending` 让路守卫（本版本回归修复重点）：
  1. 主会话存在非记账 pending action 且消息未引用记账草稿时，六位码/取消/重发确认码/普通文本一律交回通用确认边界（修复客户写操作六位码被记账运行时吞掉）；
  2. 无引用、无 pendingActionId 时，非记账语言不再被隐式草稿绑定（修复草稿活跃期普通客户查询被劫持为"请回复确认入账…"）。
  引用草稿的确认/修改/取消、隐式"确认"、"修改…"前缀、借款/区域意图与财务范围门保持不变；借款/区域独立意图在通用 pending 存在时仍归记账运行时处理。
- 迁移 `0027_customer_profile_aliases`：customers 表加 `aliases`/`tags`（JSON 数组文本，默认 `[]`）。快照投影扩展 `version/contact/budget/summary/aliases/tags`（version 供乐观锁钉死），`customerSearch` 的 LIKE 条件加 `aliases`；画像卡展示联系人/预算/别名/标签/摘要/在办商机数/更新时间。
- 客户写路径抽取为共享模块 `backend/src/customers/customerStore.js`：`createCustomer`/`updateCustomer`/`softDeleteCustomer`/`findActiveCustomerByExactName`/`countActiveOpportunities` 从 `server.js` 迁出（非复制），微信与 Web 同一份 SQL、同一套审计快照；Web 端 `/api/customers` 四个路由行为与审计 action 不变，`customerCreate`/PATCH schema 新增 `aliases`/`tags`（≤20 项、每项 ≤120 字）。
- 审计与幂等：沿用 Web 端同名 action（`customer.create/update/delete`），微信来源以 `metadata.source="weixin-assistant"` + `metadata.actionId` + requestId 区分；确认链自带 `assistant.action.create/confirm/renew/cancel/execute` 五段审计。`customer.create` 以 actionId 为实体主键（重试不重复建档），update/delete 以 `expectedVersion` 兜底（重复执行 → VERSION_CONFLICT → 不二次写）。
- 路由器新增确定性语式（不经模型）：建档/改档/删档、`查询 X`、画像句式（`X什么情况/近况/画像/资料/档案`，排除以项目/商机/报销等结尾的主语）、上下文代词（`它/这个客户`→ 会话客户）；未知字段澄清并列出可改字段。

## 与设计文档（2026-08-27-v072-customer-agent-design.md）的实施偏差

1. 键值段顶层分隔符不含 `、`（保留给别名/标签列表值），否则"别名 甲、乙"会被误拆段。
2. `changePreview.before/after` 对数组字段保留规范化数组（预览文本层再做逗号串展示），保证确认后执行的 changes 类型安全。
3. 超时确认码回复实测为 409（仓库在 scoped 查找时已将过期 action 置 expired，落不到 confirm 的 410 分支），用户可见文案与 410 分支完全一致（"确认信息无效或已过期"），测试按实际行为固化。
4. 设计第五节"weixin-agent-http-integration 扩展"的草稿共存端到端用例落在新文件 `assistant-customer-http-integration.test.js`（同一 HTTP 边界，集中一处便于维护）。
5. `修改客户 …` 指令在绑定私聊且存在活跃记账草稿时仍会被"修改"前缀的记账纠错意图优先消费（既有惯例，设计 3.6 明确要求保留"修改…"行为不变）；此场景请改用"把X的…改成…"或"改档：X，…"句式，真机验收话术已避开该前缀。

## 边界

- 不改微信确认码机制、pendingActionRepository 与 outbox 合同（零新增 outbox 消息类型）；写操作只在服务端执行，模型只读。
- 结构化数组字段（stakeholders/decisionChain 等）微信端拒绝并提示到网页修改；`contact` 变更在审计 before/after 中被脱敏器剔除（键名匹配），`metadata.changedFields` 仍可证明该字段被修改。
- 模型路由不变（文本 deepseek-v4-flash；图片/PDF deepseek-v4-flash-vision-exp）；按项目所有者授权走本地 exact-commit 生产发布，不同步 GitHub。
