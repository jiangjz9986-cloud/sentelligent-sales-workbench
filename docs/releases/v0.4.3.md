# Sentelligent v0.4.3

This patch release restores guarded production cutover compatibility with the live CentOS 7 systemd implementation. It does not change travel-reimbursement behavior, business APIs, database migrations, dependencies, or user-facing workflows.

## Changes

- Read one complete `systemctl show <service>` snapshot and extract the required properties locally instead of requesting newer properties one at a time.
- Accept an absent `DynamicUser` field on systemd 219 as an unsupported and therefore disabled feature, while rejecting `DynamicUser=yes` and every unknown value.
- Preserve compatibility with the legacy singular `EnvironmentFile=` output key used by CentOS 7.
- Keep missing, duplicate, or additional environment files fail-closed.
- Retain all v0.4.2 release identity, manifest, ownership, service command, database, backup, listener, rollback, and protected-state gates.
- Add a regression fixture that deliberately rejects the unsupported single-property query form and succeeds only with a complete snapshot.

## Deployment boundary

- The staged v0.4.2 candidate and its preflight evidence must not be edited, reused, or promoted. Deploy v0.4.3 into a new root-owned immutable release directory from the exact GitHub Release archive.
- Generate a new consistent database backup, service plan, and exact `24/24` preflight within the required freshness window.
- Stop or restart only `sentelligent-backend.service`, `sentelligent-frontend.service`, and `sentelligent-weixin-agent.service`.
- Keep shared Caddy, Qingyang, account-vault, Mihomo, and port `8797` unchanged before and after cutover.
- Require post-cutover `24/24`, HTTPS smoke `25/25` with clean test-data cleanup, and real Chrome acceptance.

## Evidence policy

Record only non-secret commit, tag, archive digest, release/evidence paths, timestamps, check counts, and protected-state fingerprints. Never record tokens, passwords, cookies, private keys, environment-file contents, database contents, or business attachments in Git or chat.
