# 森特智行 v0.5.6

## 目的

v0.5.6 修复真实微信上游 64 位数字消息 ID 的精度问题。微信返回的 `message_id` 是 19 位整数；如果先经过 JavaScript 普通数字解析，ID 会被舍入，随后入站规范化会失败并反复重试，回复无法发送。

## 修复边界

- 使用 Node.js 24 支持的 `JSON.parse` `context.source` 保留数字字面量，再把 canonical ID 作为受限十进制字符串校验。
- canonical 优先级仍为 `message_id > msg_id > client_id`；没有 canonical ID 时，备用 ID 冲突继续 fail-closed。
- 拒绝负数、控制字符、超长值和不安全的直接数值输入；保留 sender、时间戳、消息项、私聊和 delivery key 边界。
- 仅修改 vendored WeChat adapter 及其回归测试和发布元数据；不新增工具、路由、数据库迁移或前端行为。
- 不把 sender、密码、Token、Cookie、私钥、数据库内容或微信消息正文写入仓库或证据。

## 验收边界

候选必须通过本地完整质量门、GitHub 不可变归档、服务器新鲜 25/25 preflight、受控 cutover、HTTPS smoke，以及真实微信 `/clear` 往返和 worker 错误清零后，才能更新生产基线。
