# 森特智行 v0.6.19 小小视觉记账与单次投递热修

## 问题

- 微信付款图片已无损进入生产端，但服务器本地 OCR 无法稳定读取浅色、窄幅交易行，导致金额和发生日期进入手工补录。
- 微信主动发送实际上已到达用户端时，provider 可能返回空 JSON 或把零状态放在 `base_resp`；旧适配器把这类成功回执判为失败，同一 outbox 项因而持续重试并重复发送固定确认消息。

## 修复合同

- 图片付款凭证、图片发票和 PDF 发票统一使用官方 DeepSeek 视觉模型 `deepseek-v4-flash-vision-exp`；PDF 先由受控 `pdftoppm` 把最多四页转换为有界 JPEG，再提交视觉模型。
- 文字记账、销售分析、周报、行程及其他无图片/PDF的模型请求继续使用 `deepseek-v4-flash`，不会被视觉模型路由替换。
- 视觉请求关闭 thinking，只接受严格 JSON；附件内的命令或提示词始终按不可信单据内容处理。模型失败时形成待复核状态，不静默改用普通文本模型。
- 付款凭证仅显示月日时，以微信事件处理时的 Asia/Shanghai 日期作为补全年份的参考：选择不晚于参考日期的最近对应日期；画面完全没有日期时仍保持待确认。
- 付款视觉结果同时返回严格的 `documentKind`。只有明确存在发票号码、购销方、税额或价税合计等正式发票要素才转入发票仓库，普通支付截图继续生成待记账草稿。
- 微信发送接受 HTTP 成功后的空 JSON，以及顶层或 `base_resp` 中全部为数值零的 `ret`/`errcode`；任何显式非零、畸形或未知非空响应继续失败关闭。
- 每个 outbox 项通过服务端 HMAC 派生稳定、无业务信息的 provider `clientId`，同一项的网络重试复用同一个客户端幂等标识。

## 生产配置

```text
MODEL_NAME=deepseek-v4-flash
MODEL_VISION_NAME=deepseek-v4-flash-vision-exp
INVOICE_PDF_IMAGE_COMMAND=/usr/bin/pdftoppm
```

`MODEL_API_KEY` 继续只存在受保护后端配置或加密设置中；发布物、日志、报告和前端均不包含密钥。

## 回归门禁

- 真实失败付款图片通过候选视觉模块验证：模型身份正确，金额、月日补全年份、时间及商户字段均与画面一致，输出不记录原始财务内容。
- 图片直读、PDF逐页渲染、视觉失败关闭、付款字段归一化、视觉发票分类和微信固定消息闭环均有单元/HTTP集成测试。
- 微信 SDK 覆盖空 JSON、顶层状态、嵌套状态、显式拒绝、畸形响应和稳定 `clientId`；outbox 与真实 vendored worker 集成覆盖单次成功确认。
- 后端、部署脚本、发布预检、前端构建/集成/WebKit、历史密钥扫描和 exact-commit 发布包均须全部通过。

## 边界与回滚

- 基线为生产 `v0.6.18` exact commit `7f88e6379cbf7ac9fca4b189f05b17483d53b0bc`。
- 无数据库迁移；不删除微信 session、sync cursor、原始图片、记账草稿、报销记录或发票记录。
- 切换前只把那一条已被用户确认实际送达、但仍处于重试状态的旧 outbox 项终止重试；所有其他业务记录保持原样并先完成一致性备份。
- 仅重启 backend、frontend 和 weixin-agent；共享 Caddy 只检查状态与 PID。
- 本次按项目所有者授权走本地 exact-commit 生产发布，不同步 GitHub。
