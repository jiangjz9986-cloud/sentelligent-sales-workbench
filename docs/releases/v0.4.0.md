# 森特智行 v0.4.0

`v0.4.0` 新增个人差旅报销与发票闭环。版本只服务当前单账号本人，按自然周整理真实付款、票据和请款，不引入审批流或财务付款角色。

## 主要能力

- 差旅费用账本：支持早餐、午餐、晚餐、住宿、交通、招待和其他分类，一笔费用可记录多笔实际付款，并保留个人垫付、公司直付和请款资金来源。
- 稳定账单编号：每条费用使用持久化的 `EXP-...` 编号。费用账本可显示、搜索和复制该编号，CSV、A4 实际付款记录表、付款行模型和发票匹配使用同一个值，不再生成临时 `PAY-日期-序号`。
- 请款与结算：按自然周计算实际支出、可报销金额、已收请款和多退少补结果。
- 付款凭证：可在对应付款行手动上传图片或 PDF，也可由微信机器人接收文件并生成候选。OCR/模型识别结果、人工提示和冲突项进入待处理工作台，可查看原件后确认关联或拒绝关联。
- 发票仓库：支持图片/PDF上传、原件预览、OCR/PDF文本提取、DeepSeek结构化分析、冲突提示、人工修订、按费用编号或人工选择匹配、无票确认和自然周替代候选。
- 正式输出：实际付款记录按自然周生成 A4 主表与凭证附页；付款 PDF 先通过认证请求读取，再由 PDF.js 逐页渲染为 Canvas，全部页面就绪前禁止打印。发票按每页固定四个槽位合并打印，不足四张仍保持相同版式。

## 微信付款凭证识别与复核

- 微信机器入口 `POST /api/travel-expense-document-inbox` 必须携带幂等键。新请求先取得处理租约，再在数据库事务外执行本地 OCR/PDF 文本提取和付款凭证专用模型分析；同一请求重放直接返回已存响应，不再次调用 OCR 或模型。
- 图片和 PDF 原始字节只在本机用于无损存储和文本提取，不发送给模型。DeepSeek 只接收提取后的纯文本，并且只可返回金额、日期、时间、商户、支付方式、置信度和稳定警告码；发送给模型的文本副本最多 200,000 个字符，完整提取文本仍保留供人工复核。
- 只有明确的 `EXP-...`、完整人工金额/日期/时间、无证据冲突且只有一个付款候选时，才沿用自动关联。使用了 OCR/模型证据、存在冲突、候选不唯一或识别失败时一律返回 `review_required`，不自动创建付款附件。
- 登录用户通过 `GET /api/travel-expense-document-inbox`、详情和原件接口复核；`POST /api/travel-expense-document-inbox/:id/confirm` 负责确认关联，`POST /api/travel-expense-document-inbox/:id/reject` 对应界面的“不关联，保留原件”。确认操作校验待处理版本、账单所有者和付款归属，并在同一事务中创建附件及更新状态；拒绝操作将状态改为 `rejected`，原件仍无损保留。
- 原件、长度或 SHA-256 校验失败时拒绝读取。机器人回复不回显 OCR 命令、模型响应、内部路径或错误堆栈。

## iCost 接入

- 森特智行只提供 `POST /api/integrations/icost/expenses` 文本写入接口，使用独立 Bearer Token，不提供查询、修改或删除能力。
- 请求严格要求 `text`、`ledger_name`、`idempotency_key` 和 `source`；森特智行只接受 `ledger_name=出差报销` 与 `source=icost-shortcut`，可选 `captured_at` 和 `source_id`。
- 首次自动入账返回 `201`，需要人工复核返回 `202`，合法重放返回 `200`；同一幂等键内容变化、错误账本、错误来源、未授权或限流均失败关闭。
- 统一快捷指令先完成 iCost 记账，再按账本名精确分流；“出差报销”只写森特智行，“biubiu”只写轻氧，未知账本不发送到任一业务系统。两个系统使用独立 URL、Token、数据库和审计。

## 文件与数据安全

- 图片和 PDF 保存原始字节，不转码、不降低清晰度；仅在 Brotli 结果严格更小时无损压缩。
- 同一账号内按原始内容 SHA-256 去重，读取时校验原始长度和摘要；损坏文件拒绝返回。
- 付款凭证、微信待处理原件和发票原件一律返回 `Cache-Control: no-store`，不允许浏览器在退出或切换账号后复用财务文件缓存。
- 自动识别失败不删除原件，也不会将内部错误详情返回给微信；用户可在待处理工作台查看原件并手动选择账单和付款。
- iCost Token、模型密钥、微信机器令牌、登录凭据、生产环境文件和原始业务附件均不进入 GitHub Release。发布打包器对图片、PDF、Office 文件和快捷指令使用允许列表，只保留正式公开资产、品牌资产、构建产物和无密钥 unsigned 快捷指令。
- 生产预检扩展为 `24/24`，新增正式 DeepSeek 模式/端点/模型/独立密钥、iCost 配置隔离、发票提取配置以及 `DATABASE_URL`/数据库/服务 `EnvironmentFile` 路径和 SHA-256 绑定。

## 发布边界

- 发布打包器从 `v0.4.0` 对应 exact commit 的 detached 临时 worktree 重建前端并只打包该输出；本地被 Git 忽略的旧 `outputs/product-design-prototype/dist` 不参与发布，纳入归档的 tracked 源文件按 Git blob 原始字节读取。
- 数据库迁移 `0007_travel_expenses`、`0008_expense_ingestion_invoices`、`0009_lossless_document_blobs` 和 `0010_idempotency_claim_leases` 均为向前兼容迁移；应用回滚默认不恢复数据库。
- `0010_idempotency_claim_leases` 为幂等记录增加 `claim_token`。处理中的请求使用五分钟租约，超时后可由新 worker 重新取得租约；旧 worker 不能完成或释放新租约，防止重复 OCR、模型调用和附件写入。
- 只允许重启 `sentelligent-backend.service`、`sentelligent-frontend.service` 和 `sentelligent-weixin-agent.service`。
- 共享 Caddy、轻氧服务、account-vault、Mihomo 和 `127.0.0.1:8797` 必须保持不变。
- cutover 必须先验证 15 分钟内生成、权限为 `0600`、SHA-256 一致且绑定当前 release、数据库和主机的 `24/24` 预检报告；共享 Caddy 在所有服务配置下都只允许读取状态。
- 正式发布和生产状态以 `v0.4.0` GitHub Release、归档 SHA-256、部署记录、`24/24` 预检、`25/25` HTTPS 冒烟和浏览器验收证据为准。

## 发布前真实样本验收

- 使用 `D:\森特\报销\6.15-6.18未报销` 中的只读样本验收，不移动、改名或删除源文件。`6.16济南住宿.png` 的核对基准为 `227.92` 元、`2026-06-16 17:06`；`6.16济南住宿.pdf` 的开票日期核对基准为 `2026-06-17`。
- Chrome 验收必须覆盖：图片/PDF原件预览、微信待处理候选、人工确认与拒绝、`EXP-...` 复制/搜索/精确匹配、不存在编号的就地错误、付款 PDF Canvas 全部就绪后打印，以及发票每页四槽位打印。
- WebKit 付款打印专项必须证明：两份 PDF 只就绪一份时打印仍禁用；多页 PDF 的每一页都生成尺寸非零的 Canvas；全部页面状态为 `ready` 后按钮启用；点击后 `window.print()` 只调用一次。PDF 加载失败时保持禁用，重新加载成功后才允许打印。
- 完整样本验收优先使用隔离数据库。费用和发票的界面删除属于软删除，微信“拒绝关联”也会保留原件，不能作为物理清理证据；iCost 验收清理脚本只处理带精确 manifest 的 iCost 数据，不处理微信待办、手工附件或发票。若在生产上传真实样本，应按正式数据保留，除非另有经过审计的精确清理方案。
