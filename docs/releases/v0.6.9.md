# 森特智行 v0.6.9 智能截图记账稳定提交版

## 定位

v0.6.9 修复 iOS 快捷指令无法把时间变量可靠写入 JSON、导致截图提交缺少 `idempotency_key` 的问题。设备直连 V5 不再由 iPhone 生成请求 ID，而由服务器根据规范化 OCR 文本生成稳定且不可逆的防重复键。

## 修复内容

- V5 原样保留旧 iCost 快捷指令的截图、裁剪和 OCR 动作，只替换最后的 iCost 写入。
- 请求体缩减为 OCR 纯文本和固定 `source=shortcut`，移除日期、日期格式化、时间 ID、`idempotency_key` 与 `source_id` 动作。
- 截图专用接口在缺少客户端幂等键时，使用带域隔离的 SHA-256 摘要派生稳定键；摘要不包含可读财务原文。
- 同一 OCR 文本重试命中同一条待确认记录，不重复创建流水；不同 OCR 文本得到不同防重复键。
- 继续使用账号绑定的设备身份，不在手机上保存或发送账号密码字段。
- 成功提交保持静默；服务端返回错误时显示安全错误码与字段，不回显敏感信息。

## 人工确认边界

- 截图提交只创建待确认记录，不直接产生财务写入。
- 小小只接受原文精确的“确认”、以“修改”开头的字段修改和原文精确的“取消”。
- 六位码、宽泛肯定词、带标点或空白的确认均不写账。
- 只有成功送达的最新微信草稿可以确认，幂等重放不会重复记账。

## 发布边界

- 项目所有者要求直接部署生产且不同步 GitHub；本次仅保留本地提交、标签和生产不可变发布证据。
- 个人快捷指令的设备身份不写入源码、Git 历史、发布归档、日志或对话；生成的个人签名副本不得公开转发。
- 发布只切换 backend、frontend 和 weixin-agent 三个项目服务；共享 Caddy、account-vault、Qingyang 和 Mihomo 不得重启。
