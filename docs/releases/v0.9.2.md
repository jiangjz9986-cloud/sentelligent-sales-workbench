## 关键裁定与设计偏差

- **anonymous 单人开发模式语义（任务书未显式覆盖）**：`AUTH_REQUIRED=false` 时身份为 anonymous——读保持历史全库视角、写路径回落遗留池 owner（`LEGACY_OWNER='jiangjz'`，与 0031 DEFAULT 同语义）。生产恒 `AUTH_REQUIRED=true` 不受影响；该分支只为保住既有单测/本地隔离栈语义（与 `quickRecordOwnerScope` 既有先例一致）。
- **测试先写证据**：红矩阵测试单独提交（`56cbfca`，现状越权即失败——夹具本身按目标契约书写，weeklyDraft owner 必填即 422 中断），实施后 17 用例全绿。
- **serializeHospitalTenderNotice 增第三参**（`restrictMatchesToKnownCustomers`）：Web 两端点传 owner 过滤后的名映射 + 开关=true，匹配客户的 **id/理由/需求/名称四件套**只渲染映射命中者；机器同步/内部 runner/调度器路径不传开关，序列化行为零变化（比任务书"只渲染 map 命中的匹配客户"更完整——matchedCustomerIds 裸 id 也不再泄露）。
- **机器周报契约微收紧**：`weeklyDraft.owner` 降为可选后，机器**缺省** owner 时由 mismatch 判定回 403 OWNER_SCOPE_DENIED（原 schema 必填时代为 422）；mismatch 403 契约原样保留，微信侧调用方恒传 owner 不受影响。
- **修复两处微信写路径 0031 前置缺陷**：`runtimeHandlers` 的 `visit-capture.confirm` 与 `visit-capture.capture` 原先"INSERT 无 owner + 事后 UPDATE 回填"——触发器时代 INSERT 即 ABORT。改为 INSERT 即带 `context.owner`（行为等价、原子性更好）。
- **digest 集成测试账号改名**：`assistant-owner` 含连字符不合 users 账号正则（bootstrap admin 与 users CHECK 均拒绝），digest/run 加 admin 门禁后无法取得 admin 角色，harness 账号改 `assistantowner`；同因 `transaction-audit`/`quick-record-analysis` harness 账号对齐种子 owner `jiangjz`（列表/确认目标随会话硬过滤后需可见种子行）。
- **secret 扫描自查**：矩阵测试机器令牌字面量初值 `matrix-machine-token` 触发两级扫描（`matrix` 不在 placeholder 词表），改为白名单值 `test-machine-token` 并 amend 红测试提交（本会话内本地未推送提交）；冻结树两级扫描 findings=[]。
- **CRLF 行尾卫生**：编辑器在四个本已 CRLF 的 store/digest 文件中延续了 CRLF、且新建 0031 迁移混入 CR（`.gitattributes` 规定 migrations eol=lf）。本版新改/新建文件全部归一 LF（`git diff --check` 干净）；**历史遗留 CR 文件（0028 迁移/spokenDate/ops 测试组/UserManagementPage 等，本版未改动）一律不碰**，已登记总蓝图 v1.0.0-rc"行尾卫生收口"。
- **生产冒烟脚本随契约升级**：customer/opportunity 步骤 body 删 owner；weekly 步骤故意发送假 owner 并断言 `item.owner === 会话账号`（把"Web 忽略 body.owner"直接纳入生产冒烟契约）。
