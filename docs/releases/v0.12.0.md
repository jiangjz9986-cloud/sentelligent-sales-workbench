## 本次实现

### 1. 客户级主动助手

- 新增 owner/customer 级 proactive subject，记录稳定 subject key、revision、source digest、source refs 与时间戳。
- 后台 worker 按客户扫描并把建议绑定到 subject；注入的 scan/suggestion/subject 实例优先，服务与 repository 不一致时启动失败。
- 客户页、总览和其他主动助手入口读取同一持久化建议身份。
- action/risk 写回继续要求服务端预览、显式人工确认、摘要校验、owner 隔离、版本检查和幂等键；过期 preview fail closed。

### 2. 医院招标 canonical bridge

- 招标通知增加 canonical identity、revision 和 digest，bridge 以 owner、canonical notice、customer 的组合保持唯一。
- repository、matching、sync、scheduler 和 lead conversion 统一使用 canonical 数据，避免旧 draft 与新通知事实分叉。
- preview/confirm 同时绑定通知 revision/digest、客户快照和匹配证据；变更、跨 owner、损坏或缺失确认回执均拒绝重放。
- 确认后保持机会和行动引用，重复请求不重复创建业务记录。

### 3. action/risk 完整字段写回

- action 持久化建议中的 assignee、due date、priority、expected result，以及 source type/id、suggestion id、subject key/version、source digest/refs。
- risk 将建议 priority 规范映射到业务 severity，同时保留 evidence、owner 和相同的 provenance 链。
- 创建结果、审计和重放回执使用持久化后的真实字段，不用前端预览值伪装写入完成。

### 4. CSV/XLSX 客户批量导入

- 新增 `POST /api/customer-imports/preview`、`GET /api/customer-imports/:batchId`、`POST .../confirm` 和 `POST .../cancel`。
- multipart 请求只接受 `file` 与可选 JSON `mapping`；owner 从认证会话注入，body、form 或文件中的 owner 不可覆盖会话身份。
- 支持带 BOM 的 UTF-8 CSV、CRLF、转义引号、嵌入换行和 XLSX；文件大小、行数、列数、单元格长度与格式解析均有保守上限。
- 预览产生稳定 batch/row digest、字段映射、错误和服务端逐行动作。前端只展示动作，不允许客户端改写服务端计划。
- 同 owner 的 canonical name 或 alias 可合并；不同 owner 不互相匹配。确认前重新核对文件摘要、预览摘要和客户快照。
- confirm 在单个 SQLite immediate transaction 中提交 create/merge/skip/reject、逐行审计和批次审计；失败不会留下部分客户。原始文件字节和未映射列不持久化。
- 客户页面板同时提供桌面表格和移动卡片；文件或映射变化会使预览失效并禁用确认，直到重新预览。

- 不包含生产数据库迁移、SSH 写入、服务重启、流量切换、真实模型质量结论或真实微信/PushPlus 通知验收。
- 不包含读取 iCloud 中的密钥、样表或资料；所有导入数据均由验收脚本现场生成。
- 浏览器脚本证明 CSV UI/API 全链；XLSX 的 ZIP/XML 解析与边界由后端自动化测试证明，不把未执行的 XLSX 浏览器上传写成已完成事实。
