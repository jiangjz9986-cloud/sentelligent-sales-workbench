# 森特智行 v0.6.2 历史候选说明

## 目的

v0.6.2 在 v0.6.1 账号级 Shortcut Token 边界上开放真实记账：用户继续只在 iOS 快捷指令填写一个森特账号 Token；后端按固定森特目录完成幂等、租约、失败恢复和审计。

## 发布内容

- 新增 `0018_shortcut_bookkeeping_entries`，保存账号、选择分类、请求哈希、处理租约和本地差旅关联；原始幂等键只保存 SHA-256 哈希，并按账号全局唯一。
- 注册 `POST /api/integrations/shortcut/bookkeeping`：
  - `出差报销` 支出经服务端分析后创建森特差旅费用和支付记录；信息不足时保留为 `review_required` 快捷指令记录和审计，并在森特网页“差旅费用 → 付款凭证 → 快捷指令待复核”提供 owner-scoped 列表、详情、补录确认、拒绝和重新识别入口。确认使用处理租约与幂等状态，只有成功确认才创建真实费用和付款记录。
  - `出差报销` 首期只开放支出；收入分类在目录中保留为空并由 API 拒绝，避免映射为不存在的本地收入模型。
-- 本候选不包含 `biubiu`、轻氧 bridge 或跨系统凭据；快捷指令只写森特本地出差报销。
- `GET /api/integrations/shortcut/verify` 只有在账号 Token 有效且森特本地微信复核配置完整时返回 `bookkeepingReady=true`。
- 后续 v0.6.3 候选使用 0019 durable 微信确认 outbox，并由新的生产门禁校验 owner/sender 绑定。

## 安全与失败边界

- iOS 快捷指令和用户只持有森特账号 Token；不保存或读取任何远端 bridge credential。
- 识别不完整、确认码冲突、发送失败或状态不明全部 fail closed；outbox 只记录引用和固定错误码，允许安全重试。
- 快捷指令生成的幂等键只基于 OCR 文本、分类和备注，不依赖运行时日期；整条快捷指令在响应丢失后重跑仍使用同一 key。

## 发布与回滚顺序

1. 先在森特候选 worktree 完成本地快捷指令、微信复核和迁移验收。
2. 运行 backend/frontend/full release gates，确认 0018/0019 迁移和本地 outbox 可恢复。
3. 生产只需配置森特账号、微信 owner/sender 白名单和本地助手密钥；不配置远端记账凭据。
4. 原子切换森特后先验证 Token、catalog、本地出差报销和微信合成确认；确认前必须保持零费用/付款写入。

本文件只描述候选发布合同，不表示 tag、GitHub Release 或生产部署已经完成。
