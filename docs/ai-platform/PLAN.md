## 1. 交付目标

把当前业务后端中分散的 AI 调用、Agent 配置、主动分析调度、用量记录和预算控制集中到独立 AI 服务，使其可独立运行、发布和回滚。

交付必须同时包含：

1. 独立 AI 运行服务、专用数据库和可视化管理后台。
2. 全部现有模型调用的统一入口，包括文本、销售决策、票据视觉与 ASR。
3. 任务、模型尝试、工具执行和结果投递的可追踪记录。
4. Agent 与业务规范的草稿、测试、发布、版本固定和回滚。
5. 持久任务、并发限制、预算预占及结算、主动调度和有限重试。
6. 与现有权限、人工确认、业务快照、结果卡和通知机制兼容的适配层。
7. 自动化测试、浏览器验收、发布制品、备份和恢复演练材料。

不能只完成一个模型代理或静态管理页面，就把整个平台标记完成。

## 2. 范围与非目标

### 本期包含

- 对现有功能的 AI 执行链路进行改造，保留原有业务行为和结果合同。
- 独立服务采用现有 Node.js 24 技术体系；平台数据单独使用 SQLite。
- 管理界面复用 React、Vite、现有品牌和图标体系，但使用独立源目录及构建目录。
- 开发及测试默认只使用模拟供应商、本地虚构数据，不消耗真实模型额度。
- 保留业务系统统一登录；管理代理和服务身份接入在共享文件整合窗口进行。
- 提供 systemd 运行方案；本期不强制安装 Docker。

### 本期不包含

- 拆分客户、商机、差旅等业务服务，迁移整个业务数据库或重写现有产品前端。
- Kubernetes、Redis、Kafka、向量数据库和通用拖拽工作流引擎。
- 每个 Agent 一个容器，或通过后台任意执行 SQL、Shell、代码和外部 URL。
- 自动训练模型、承诺新模型质量优于当前模型、自动计费收款。
- 自动部署生产、自动迁移旧机器操作系统、操作另一任务的进程。

操作系统迁移是另行排期的运维事项，不与本项目的代码交付混为一体；生产部署前必须重新核实运行环境与支持风险。

## 5. 数据所有权与存储

### 业务端持有

- 用户身份与角色、客户、商机、记录、动作、风险、差旅财务、业务通知和正式审计。
- 人工确认、乐观锁、软删除、业务幂等与事务规则。
- 业务对象的读取权限和最新版本校验。

### 平台持有

- `providers`、`models`、`price_versions`：供应商及模型能力和不可变价格版本。
- `agent_definitions`、`agent_versions`、`standard_versions`、`agent_releases`：定义、草稿和发布快照。
- `tasks`、`task_attempts`、`tool_runs`、`task_events`：任务、尝试、工具及事件。
- `budget_policies`、`budget_reservations`、`usage_ledger`：预算、预占和不可覆盖的用量台账。
- `schedules`、`schedule_runs`、`result_deliveries`：调度、去重和结果投递。
- `admin_audit`：配置、发布、预算与凭据变更审计。

平台迁移从自己的 `0001` 开始，不能占用 `backend/src/db/migrations/0046+` 或修改业务迁移注册表。所有表应在适用处明确 `owner` 或系统作用域；普通用户不能读取全局数据。

生产数据目录必须在 immutable release 之外；本地开发数据仅放本工作树的忽略目录。不同任务禁止使用同一个 SQLite 文件。

旧 AI 结果仍留在业务端读取。迁移不能触发历史分析重跑，也不能把旧通知重新入队。

## 6. 身份与安全

1. 浏览器不接触供应商密钥或平台内部服务凭据。
2. 业务服务向平台提交由服务端生成的身份上下文；客户端正文中的 `owner`、角色和权限不能成为信任依据。
3. 平台区分执行、读取本人结果、管理配置、发布和读取全局成本等能力；管理操作仍要求业务端管理员身份。
4. 独立开发使用仅限回环地址的测试身份。任何开发认证捷径在生产模式必须拒绝启动。
5. 内部认证机制、签名范围、有效期、重放防护和轮换方式在 M1 合同测试中冻结；不可使用一个前端可见 Token 获得管理员权限。
6. 工具是固定注册 API，不接受任意地址、数据库语句、Shell 或动态代码；身份在整个工具链中保持不变。
7. Prompt 与规范属于可配置内容，不具备修改安全下限的能力；模型输出始终是不可信建议。
8. 使用业务工具写入时，由业务后端再次检查权限、原始确认凭据、对象版本和幂等键；模型不能制造“已确认”状态。
9. 供应商网络地址来自受保护配置，拒绝凭据型 URL、URL 中的查询密钥、未授权重定向和不在允许范围内的目标。
10. 敏感输入不写普通日志；确需恢复任务的 payload 与日志元数据分开存储，限定权限、加密和保留期限。
11. 音频与原始媒体不因为新平台而变成长期存档；沿用已有临时媒体上限、超时和清理语义。
12. 平台不直接发送微信或 PushPlus 业务通知；结果经业务端现有 outbox 与通知权限处理。

## 7. 任务与调度语义

- 一次用户业务操作对应一个任务，一次任务可以对应多次供应商尝试和工具调用。
- 基本状态：`queued`、`running`、`succeeded`、`failed`、`cancelled`、`expired`。
- 业务“待确认”是结果中的业务状态，不允许平台把它当作写入授权。
- 接收阶段完成身份、功能、参数、重复请求、预算与配置版本校验。
- 短任务可以有界等待结果；长任务返回任务 ID，通过读取状态继续，不无限占用 HTTP 请求。
- 幂等键按调用方、owner、任务类型及稳定输入摘要限定；同键不同输入返回冲突。
- 执行器使用持久租约、期限及尝试号，支持进程崩溃恢复；过期执行器不能覆盖新尝试结果。
- 客户资料或证据变化时，缓存键必须包含 owner、任务类型、证据摘要、Agent 版本及模型策略版本。
- 人工交互请求优先于后台批量任务；限制全局、用户、功能和供应商并发，防止后台任务长期占满执行器。
- 超时或取消需要传播至供应商请求与受控子进程；取消不代表供应商一定没有计费。
- 状态不明的供应商请求记录 `unknown` 计费状态，不承诺外部调用 exactly-once；业务结果投递和正式写回必须幂等。
- 主动分析只扫描用户有权访问的对象，由业务端提供有界分页接口或事件快照，不允许平台直接全库读取。
- 新旧调度器交接必须有明确的停旧、排空或标记、启新与回滚顺序，且同一个调度键只有一个活跃所有者。
- 调度器不能依赖“打开页面”才运行，管理台需要显示上次运行、下次计划、租约、积压和最后错误。

## 8. Agent、规范和发布

每个 Agent 至少包含：`id`、版本、任务类型、Prompt、规范引用、输入输出 Schema、模型策略、允许工具、步数/时长/Token 上限、来源要求和降级策略。

规范分为三层：

1. 代码中不可降低的安全底线。
2. 可发布的公共业务标准，例如事实/推断/未知分离及来源保留。
3. 功能专用标准，例如销售决策评分、发票识别候选和周报结构。

发布流程：草稿 -> 校验 -> 离线案例测试 -> 管理员发布 -> 新任务生效。

- 保存草稿不影响生产执行。
- 发布版本不可原地改写；回滚通过切换发布指针完成。
- 任务接收时固定 Agent、规范、模型策略和价格版本；在途任务不能混用新旧版本。
- 测试版本与真实运行数据、真实通知必须隔离。
- 已有工具范围内新增 Agent 可以配置化；新工具、权限、业务写操作仍需要开发和审查。
- 修改输出 Schema 时必须验证业务结果适配器兼容，不能静默破坏现有结果卡。

## 9. 成本、预算与费用口径

### 计量

- 用量优先采用供应商返回值，保存输入、输出、缓存等不同计费项和请求标识。
- ASR、图像或其他接口按供应商实际计费单位记录，不能一律折算为 Token。
- 每次尝试都记账，包括最终解析失败、重试和降级之前已发生的消耗。
- 金额使用明确货币与整数最小计量单位，避免浮点累计误差；不同货币不在没有汇率来源时直接相加。
- 将供应商实际账单、按用量与价格计算的费用、估算和未知状态分开表示；没有用量不等于零成本。
- 规则执行、缓存返回和真正模型执行要分别标识，不能把规则回退标为模型成功。

### 预算

- 全局、用户、功能和 Agent 可叠加次数与金额限制。
- 供应商调用前在事务内预占预算，并发请求不能越过总额。
- 结束后结算；未知计费结果保留可核对状态，不通过立即释放所有预占让重试绕过预算。
- 配置预算周期、时区、告警阈值与硬限制；修改预算也需要审计。
- 预算存储不可用时拒绝新的付费调用，不能绕过台账直接访问供应商。

### 功能收费

首期记录“功能成本”和可选的功能收费规则，不实现支付收款。供应商成本、内部费用分摊与用户收费必须分账，同一功能可能消耗多次模型调用。

## 10. 管理前端

管理界面面向日常运营和排错，采用紧凑表格、筛选、详情抽屉和明确的编辑/发布动作，不制作营销首页。

一级视图：

1. 概览：调用量、成功/失败、费用、预算占用、队列和供应商状态。
2. 任务：按功能、用户、Agent、状态和时间筛选；详情显示完整尝试链。
3. Agent：列表、编辑、规范关联、输入输出定义、测试、发布、版本差异和回滚。
4. 规范：公共/功能标准、引用关系和发布版本。
5. 模型与凭据：能力、连接设置、密钥掩码、价格版本、超时和允许任务类型。
6. 调度：触发条件、时间计划、启停、下次执行、积压和失败原因。
7. 成本与预算：维度汇总、账目状态、预算设置和导出。
8. 管理审计：谁在什么时候修改或发布了什么，不显示秘密值。

必须实现加载、空数据、错误、无权限、保存冲突、运行中、取消中和超额等真实状态。手机视口保持可读，宽表应使用受控滚动或窄屏详情，不允许页面整体横向溢出。

| M6 视觉与 ASR | 票据、视觉、语音协议适配，媒体与取消清理，完整用量口径 | 各功能合同、边界、取消、超时、清理与回退标识测试通过 |
| M7 整合与交付 | 合并对方已验收修复、共享文件串行整合、全量回归、发布包、备份恢复与回滚演练 | 全部验收用例有证据；生产部署是否执行单独决定 |

M3 和 M4 可以在接口冻结后并行；M5 依赖 M2/M3，M6 的媒体合同可提前设计但不能绕过现有安全门。不存在“管理页面完成就平台完成”的捷径。

## 12. 发布、运行与回滚

- AI 服务独立版本，初始研发版本计划为 `0.1.0`；暂不改业务根目录版本、CHANGELOG、锁文件或正式 release。
- 本地端口从空闲端口选择，计划池为 API `18997`、管理页面 `18088`；绑定回环地址，冲突时选择新端口，不终止现有监听进程。
- 本任务脚本只管理自己记录的 PID、工作目录和启动标识，不使用 `pkill node`、全局清理或另一工作树的 dev stop。
- 平台部署方案使用单独服务单元和数据目录；上线前需要对当前主机重新做资源、系统兼容性和安全校验。
- 发布包含平台制品、配置 Schema、数据库迁移与 API 兼容版本；数据库和密钥不进入制品。
- 业务接入按功能切换，初始关闭；正式开通某功能前验证平台可用、计量开启和权限配置。
- 平台宕机时普通业务继续工作；AI 功能明确失败或进入已声明的队列，不在运行时偷偷回退旧供应商直连。
- 回滚优先切回兼容的平台上一版本；切换执行路径必须受控且审计。恢复旧路径不能把两条模型或调度路径同时打开。
- 迁移使用兼容性优先、先扩展后收缩的方式；旧数据不做不可逆清理。
- 备份恢复至少验证数据库完整性、版本一致性、预算与租约恢复，以及任务恢复不会重复写回。

## 13. 风险与处理

| 风险 | 对策 |
| --- | --- |
| 与并行任务冲突 | 独立工作树；新增目录独占；共享文件先约定后串行整合 |
| 平台单点故障 | AI 与业务 CRUD 解耦；超时、熔断、健康检查、持久状态及可恢复执行 |
| 重试重复计费 | 每次尝试记账；严格上限；未知结果单独核对；不承诺外部 exactly-once |
| 调度重复执行 | 调度所有权交接、租约与幂等；旧历史不自动重新入队 |
| 配置破坏业务 | 输出合同测试；版本固定；先测试后发布；回滚发布指针 |
| Prompt 绕过授权 | 安全由业务后端和平台工具执行层强制，不交给模型决定 |
| 日志泄露 | 元数据优先、敏感 payload 隔离、加密、掩码、访问控制与保留期限 |
| 内存或磁盘压力 | 有界队列和响应、媒体 TTL、日志轮转、并发限制、资源验收 |
| 老版本混入 | 记录精确基线与变更提交，不依据旧 README 或旧内存快照判断当前生产 |
| 测试冒充真实质量 | 模拟供应商验证协议；真实样本质量与费用验收单独报告和授权 |
