## 新设备恢复步骤

1. 安装 Git、GitHub CLI、Node.js 24、npm 和 Chrome。
2. 克隆仓库并检出 `v0.4.4`：

   ```bash
   git clone https://github.com/jiangjz9986-cloud/sentelligent-sales-workbench.git
   cd sentelligent-sales-workbench
   git switch --detach v0.4.4
   ```

3. 安装依赖：

   ```bash
   npm ci --prefix backend
   npm ci --prefix outputs/product-design-prototype
   ```

4. 通过可信的带外渠道转移本机私密配置和 SSH 私钥。不要从 GitHub、聊天记录或公开网盘复制凭据。转移后检查文件 ACL 和 SHA-256。
5. 按 `.env.example` 创建本机配置，至少按需要配置以下变量名（值只在私密环境中保存）：

   - `AUTH_ACCOUNT`、`AUTH_PASSWORD_HASH`、`AUTH_SESSION_SECRET`
   - `MODEL_PROVIDER`、`MODEL_API_KEY`、`MODEL_BASE_URL`、`MODEL_NAME`、`MODEL_TIMEOUT_MS`
   - `AMAP_WEB_SERVICE_KEY`、`VITE_AMAP_WEB_JS_KEY`、`VITE_AMAP_SECURITY_CODE`
   - `WEIXIN_AGENT_API_TOKEN`、`WEIXIN_AGENT_BACKEND_URL`、`WEIXIN_AGENT_OWNER`
   - `ICOST_WEBHOOK_TOKEN`、`ICOST_WEBHOOK_OWNER`
   - `INVOICE_OCR_COMMAND`、`INVOICE_PDF_TEXT_COMMAND`、`INVOICE_OCR_LANGUAGES`

6. 运行本地质量门：

   ```bash
   npm run qa:full
   ```

7. 继续生产开发前先阅读 `docs/发布与回滚操作手册.md`、`docs/正式交付验收手册.md` 和 `docs/部署记录.md`。生产证据有时效，必须在新设备重新采集，不能复用旧报告。
