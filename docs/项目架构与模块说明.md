# 项目架构与模块说明

更新时间：`2026-08-28`（v0.8.4 工程健康回填）

## 1. 系统边界

这套系统是销售工作台，不是通用 CRM。它负责保存销售过程证据、组织下一步动作、识别风险并生成可复核的 AI 结果；小小（微信 AI 助手）承接移动端录入、确认与提醒。客户主数据、商机状态和资源决策可以人工维护；AI 不得绕过人工确认直接修改关键业务档案。

## 2. 请求与数据流

```text
Chrome / Safari / PWA          微信私聊（小小）
  -> React 工作台                -> weixin worker（vendored SDK）
  -> Cookie + CSRF JSON API      -> 机器 Token 事件 API（幂等键）
  -> Node.js 24 后端 <------------+
  -> SQLite 业务库与审计日志（迁移 0001–0028）
  -> DeepSeek / AMap / WeChat Clawbot
```

浏览器只持有展示会话和当前 CSRF。模型、地图 Web Service、微信机器凭据只存在于后端生产环境。

### 三个调度器

| 调度器 | 节奏 | 边界 |
| --- | --- | --- |
| 招标轮巡（`hospitalTender`） | 白天窗口（09–20 点）每小时一批 | 持久化游标/快照/锁；失败记 `last_error` 自愈 |
| 到点提醒（`actionReminders`） | 分钟级扫描 remind_at | worker 离线跳过不标记、恢复补发，迟到 >24h 标注过期 |
| 每日晨报（`dailyDigest`） | 每日早晨（Asia/Shanghai） | 聚合行程/待办/风险/新招标；周末不补发 |

## 5. 数据层

迁移位于 `backend/src/db/migrations/`，现行 `0001`–`0028`（共 27 项，`schema_migrations` 为准；`0028` 为待办提醒列）。关键迁移：`0014`–`0016` 招标监测、`0017` 快捷指令 Token（已退役）、`0019` 微信 outbox、`0022` 助手运行记录、`0023` 助手业务上下文、`0024` 请款分摊、`0025` 差旅区域档案、`0026` 招标活跃窗口、`0027` 客户 aliases、`0028` 待办提醒。

数据规则：

- 文件数据库启用 WAL、外键和 busy timeout；生产库只用项目 runtime node（≥24）的 `node:sqlite` 访问，严禁系统 sqlite3 3.7.17 触碰 WAL 库。
- 业务写入带 `version`，PATCH/DELETE 使用 `If-Match` 防止覆盖他人修改；删除采用软删除。
- 快速记录确认使用幂等键和事务，业务写入与审计一起提交。
- AI 分析、销售决策和行程保存当时快照，历史读取不重新调用外部服务。
- 审计脱敏边界：客户 `contact` 在 before/after 中被脱敏器剔除（预期行为），`changedFields` 仍可证明该字段发生过改动。
- 微信 outbox：`queued/processing/failed` 三态，`failed` 为终态；`requeueFailed` 仅允许 retryable 错误码重开，`closePending` 用于纠错/取消后关闭旧草稿消息。
- 生产备份用 SQLite 一致性方式生成，再执行 `quick_check`、外键检查和 SHA-256；每日 02:30 备份 timer + 发布制品归档见 v0.8.0。

数据库和备份始终位于 release 目录之外。部署源码不能覆盖生产数据。

## 6. AI 与外部服务

### DeepSeek

生产文本模型 `deepseek-v4-flash`；付款凭证与发票图片使用独立视觉模型（PDF 先由受控 Poppler 渲染有界页面图片）。快速记录、周报、销售决策、行程优化、小小各 agent 使用不同业务合同。销售决策结果是诊断材料，写回一律人工确认。

### 高德

浏览器负责地图与可用时的坐标解析；后端进行逆地理复核、距离矩阵和驾驶路线请求。历史行程读取保存的路线快照。

### 微信（小小）

微信 worker 是独立 systemd 服务，vendored SDK 通过机器 Token 调用事件 API。阶段词表当前在后端 `stageVocabulary.js` 与前端 `kanbanStages` 各存一份（注释互指 + `stage-strip` 同序守护测试兜底；下沉单一来源为登记债项）。

## 7. 生产运行

| 服务 | 监听/用途 | 约束 |
| --- | --- | --- |
| `sentelligent-backend.service` | `127.0.0.1:8897` | 固定到具体 release 的后端入口 |
| `sentelligent-frontend.service` | `127.0.0.1:8088` | 固定到具体 release 的静态服务 |
| `sentelligent-weixin-agent.service` | 微信 worker | 固定到具体 release 的 worker 入口 |
| `sentelligent-caddy.service` | 公网 HTTPS 和反向代理 | 共享服务，只读核验，不随应用重启（变更需 restart 显式操作） |
| `sentelligent-daily-backup.timer` | 每日 02:30 备份 | systemd 219 语法（无时区后缀）；发布窗口 fail-closed 跳过 |

服务器为 CentOS 7（systemd 219）、时区 Asia/Shanghai、项目 runtime node v24。`current` 只能帮助人工识别当前版本；`.production-cutover.lock` 为 flock 残留锚点，属正常现象（见部署记录·运维注意事项）。

## 8. 安全边界

- 生产凭据只进入受权限保护的环境文件；密钥不落盘、不进终端输出。
- Cookie 使用 `HttpOnly`、`Secure`、`SameSite=Lax`，会话期七天。
- 所有业务写入经过认证、CSRF、Origin、输入校验和审计。
- 机器 Token 采用单独能力白名单，不能替代用户身份；sender 白名单 + 私聊限定。
- 发布包拒绝 `.env`、数据库、备份、私钥、日志、运行状态和依赖目录。
