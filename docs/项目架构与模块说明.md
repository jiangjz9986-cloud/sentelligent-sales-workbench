# 项目架构与模块说明

更新时间：`2026-07-29T01:19:27.509+08:00`

## 1. 系统边界

这套系统是销售工作台，不是通用 CRM。它负责保存销售过程证据、组织下一步动作、识别风险并生成可复核的 AI 结果。客户主数据、商机状态和资源决策可以人工维护；AI 不得绕过人工确认直接修改关键业务档案。

## 2. 请求与数据流

```text
Chrome / Safari
  -> React 工作台
  -> Cookie + CSRF JSON API
  -> Node.js 24 后端
  -> SQLite 业务库与审计日志
  -> DeepSeek / AMap / WeChat Agent
```

浏览器只持有展示会话和当前 CSRF。模型、地图 Web Service、微信机器凭据只存在于后端生产环境。前端高德 JS Key 仅用于地图和浏览器地址解析，服务端仍会复核坐标并执行路线请求。

- 列表默认只展示摘要；详情默认只读。

- 搜索只影响当前模块。
- 长内容在工作区内部滚动，主导航和标题保持可见。
- 快速记录默认语音模式；历史分析只读取已保存结果。

## 5. 数据层

迁移位于 `backend/src/db/migrations/`。生产已应用 `0001`、`0002`、`0003`、`0005`、`0006`。

数据规则：

- 文件数据库启用 WAL、外键和 busy timeout。
- 业务写入带 `version`，PATCH/DELETE 使用 `If-Match` 防止覆盖他人修改。
- 删除采用软删除；列表默认过滤已删除数据。
- 快速记录确认使用幂等键和事务，业务写入与审计一起提交。
- AI 分析、销售决策和行程保存当时快照，历史读取不重新调用外部服务。
- 生产备份用 SQLite 一致性方式生成，再执行 `quick_check`、外键检查和 SHA-256。

数据库和备份始终位于 release 目录之外。部署源码不能覆盖生产数据。

## 6. AI 与外部服务

### DeepSeek

生产模型为 `deepseek-v4-flash`。快速记录、周报、销售决策和行程顺序优化使用不同业务合同。销售决策 Agent V1 已拆为短核心提示、场景 playbook、结构 Schema 和确定性回退，完整规则文档不会在每次请求中重复发送。

销售决策结果是诊断材料。阶段升级、资源投入和客户/商机/行动/风险写回继续要求人工确认。

### 高德

浏览器负责地图和可用时的坐标解析；后端进行逆地理复核、距离矩阵和驾驶路线请求。历史行程读取保存的路线快照，避免费用和结果漂移。

### 微信

微信 worker 是独立 systemd 服务。绑定状态通过后端查询，机器 Token 只允许访问声明的微信路由。下一阶段重点是消息幂等、草稿持久化和单消费者保护。

## 7. 生产运行

| 服务 | 监听/用途 | 约束 |
| --- | --- | --- |
| `sentelligent-backend.service` | `127.0.0.1:8897` | 固定到具体 release 的后端入口 |
| `sentelligent-frontend.service` | `127.0.0.1:8088` | 固定到具体 release 的静态服务 |
| `sentelligent-weixin-agent.service` | 微信 worker | 固定到具体 release 的 worker 入口 |
| `sentelligent-caddy.service` | 公网 HTTPS 和反向代理 | 共享服务，只读核验，不随应用重启 |

Node ESM 会把 `import.meta.url` 解析到真实目录，而 `process.argv[1]` 可能保留符号链接路径。为避免严格入口守门跳过启动，systemd 直接引用不可变 release 路径。`current` 只能帮助人工识别当前版本。

## 8. 安全边界

- 生产凭据只进入受权限保护的环境文件。
- Cookie 使用 `HttpOnly`、`Secure`、`SameSite=Lax`，会话期七天。
- 所有业务写入经过认证、CSRF、Origin、输入校验和审计。
- 机器 Token 采用单独能力白名单，不能替代用户身份。
- 发布包拒绝 `.env`、数据库、备份、私钥、日志、运行状态和依赖目录。
- 当前根 HTML 缺少 API 已有的 HSTS/CSP 头。修复应落在前端静态响应，不直接改共享 Caddy。
